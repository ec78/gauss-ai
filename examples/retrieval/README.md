# Retrieval Examples

## Purpose

This directory stores example outputs from the lightweight command documentation lookup prototype.

The examples help evaluate whether the GAUSS Code Assistant can distinguish verified command-specific documentation from command category discovery and unresolved retrieval gaps.

## How To Run

```text
python scripts/command_doc_lookup.py olsmt --docs-root "C:/Users/eclow/Documents/GitHub/docs/docs"
```

Keyword-focused retrieval:

```text
python scripts/command_doc_lookup.py olsmt --docs-root "C:/Users/eclow/Documents/GitHub/docs/docs" --keywords intercept formula missing ctl olsmtControl output returns
```

Replace the docs root with the local path to an official GAUSS documentation checkout.

Keyword snippets are evidence from the matched official documentation page. They should not be treated as interpretation by themselves.

Quote multi-word keyword phrases (for example `"not found"`) so they are searched as one phrase rather than split into separate single-word keywords.

## Suggested Pilot Commands

- `olsmt`
- `strindx`
- `strlen`

Do not add generated lookup output unless the script was actually run against local official documentation.

The current `olsmt.lookup.json` and `strindx.lookup.json` files were generated by running the prototype with keyword-focused retrieval against a local official GAUSS documentation checkout.

## Schema Status

The existing lookup JSON files predate, or only partially align with, the formal evidence schema in `schemas/command_lookup_evidence.schema.json`.

They remain useful as v0.4.0 prototype outputs and evaluation evidence. Future retrieval examples should be schema-aligned and validated once the lookup script and validator support that workflow.

Future schema-aligned lookup outputs should pass:

```text
python scripts/validate_lookup_evidence.py path/to/evidence.json
```

Use `--strict` when warnings should block release readiness, and `--json` when another tool needs machine-readable validation results.
