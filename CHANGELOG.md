- Added `v0.87.0` Handoff Binding and Precondition Coverage. It fixes six small, pre-existing findings from live evaluations 76.x and 77.x. One of them concerns the consent contract itself.
- **Fixed (77.x finding 2): a reply was not bound to the prompt the user answered.** `gauss_execution_prepare` silently replaced a pending request, and `gauss_execution_decide` took no identifier, so a "yes" after two prepares ran the second request.
  - `gauss_execution_decide(session_id, response_text, request_id)` now acts only on the pending request whose `request_id` it is given, checked before the reply is parsed. `request_id` is optional in the schema but required in effect: without it the answer is `request_id_required`, which explains what to send (some clients keep stale tool descriptions). A prompt a later prepare replaced is `request_superseded`; any other id is `request_not_pending`. None of these creates an approval or runs anything.
  - A prepare that replaces a pending request says so (`replaced_request_id`, `notice`).
  - Every decide outcome (`unrecognized`, `declined`, every execution result) echoes `request_id` and `request_digest`.
  - **Breaking for MCP clients:** a `decide` call without `request_id` no longer runs anything.
- **Fixed (76.x finding 3): a refused prepare spent its `validation_id`.** The id was consumed before the checks, so a resubmission was told `unknown_or_used_validation_id`. An id is now spent only by a prepare that returns a prompt; `real_gauss_not_allowed`, `validation_stale` and `request_rejected` leave it usable and repeat on resubmission.
- **Added (76.x finding 2): `gauss_session_start` reports `real_gauss_allowed`,** the server operator's `GAUSS_AI_MCP_ALLOW_REAL_GAUSS=1` opt-in, plus an `execution_hint` when the runner is `gauss` without it. It says nothing about whether the executable launches.
- **Fixed (77.x finding 3): the prompt showed a "Workspace parent" the run never used.** Handoff runs always execute in a new temporary directory, deleted afterwards (the v0.78.0 design). The prompt now says so ("Runs in: a new temporary directory, deleted after the run"), and the workspace parent is no longer put on the request, so the digest binds only what the prompt shows. This affects `gauss-ai chat` and MCP alike; guided repair is unchanged.
- **Fixed (77.x finding 1): the `/` operator skipped the precondition registry.** A literal singular matrix was `not_ready` through `inv(a)` but `HANDOFF_CANDIDATE` through `eye(2) / a`. Spot checks show `/` solves only when both operands are matrices (`G0048` for a singular square divisor, `G0121` for a rank-deficient or wide one) and divides element-wise when either is a scalar, even a scalar a call returns. A literal divisor (inline, or a name traced to a literal) is now checked: `not_ready` when the dividend is a known matrix, `review_required` when its shape is not known, nothing for a scalar dividend.
- **Added (76.x finding 6): `eigh` and `eighv` require a symmetric input.** Both read only the lower triangle and return another matrix's eigenvalues for a non-symmetric input, without any error. A non-symmetric or non-square literal is `not_ready`; a runtime input is `review_required`, as for `invpd`.

- **Fixed (75.8, 75.18): a brace literal assigned to a structure member was INVALID.** `ctl.bStart = {0, 0};` gave `let_statement_shape` ("target must be a plain name"), a rule with no evidence behind its member branch. A member path written without whitespace is now a valid target, like a plain name: `s.x`, `s.a.b`, `let s.x`, or `d0[1].x` for an element of a structure array. Still INVALID, each with its own message:
  - a literal followed by anything (`s.x = {1, 2}';`, `G0008`);
  - a target ending in an index (`v[1] = {5};`, `s.x[1:2] = {7 8};`). GAUSS rejects these (`G0046`/`G0047`/`G0008`), or, for a 1x1 index on a row, silently replaces the whole variable with the literal;

- **Fixed (75.19): word operators were read as calls.** `(x .< 2) .or (x .> 8)` made `or` an unknown call (`not_ready`), and `.and (` grounded by accident on `logical-and.rst`. Inside a call argument, the same code was a false `call_argument_missing_separator` INVALID, as was `selif.rst`'s own `(...) .and (...)` example.
  - The eleven word operators (`and`, `or`, `not`, `xor`, `eqv`, `eq`, `ne`, `lt`, `le`, `gt`, `ge`, with or without `.`) run in every position and are reserved words (`G0276`). They are now blanked from the shared call-scan view and treated as operators by the adjacency check.
  - `not` used as a binary operator (`s not t`, `G0136`) is still INVALID.
  - A snippet whose only "documented call" was the accidental `.and (` now has none, so it is `not_ready` with that reason.
- **Fixed (75.20): every structure definition was a matrix literal.** `struct Name { matrix b; ... };` gave `matrix_literal_row_separator`. Definitions are now recognized from whole statements, and the new INVALID rule **`struct_definition_shape`** checks each member: one of `scalar`, `matrix`, `array`, `string`, `string array`, `sparse matrix` or `struct Type`, then exactly one name.
  - The malformed shapes GAUSS rejects with `G0008` are flagged: pointer members, `a, b`, two names, no type, an initializer, an unknown type word, a statement or literal in the body, a missing name, an indexed name, a nested definition, and a nameless definition.
  - A valid definition is a validated construct (`struct_definition`), so such code can reach `HANDOFF_CANDIDATE`. A `}` followed by anything but `;` or one declared name is an unknown construct.
- Not modelled (disclosed): structure types. A literal assigned to a `scalar` member (`G0071`), an undefined member type or a declaration before the definition (`G0507`), and a different redefinition (`G0467`) are not caught; they fail when run and are reported honestly.
