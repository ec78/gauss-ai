# Changelog

This file records notable changes to the GAUSS AI framework.

## [Unreleased]

- Added `v0.55.0` Verified Diagnostic Coverage Expansion: grew the verified GAUSS error catalog from 5 to 11 entries, all backed by real GAUSS 26.1.1 runtime reproduction (`tgauss.exe -b` in disposable scratch directories, no package install/removal, no license/config changes).
- Added six new catalog entries: `G0058` (Index out of range), `G0159` (Wrong number of parameters), `G0104` (Argument must be positive), `G0071` (Type mismatch), `G0048` (Matrix singular), `G0047` (Rows don't match) — each real-runtime-verified only, not yet cross-checked against official documentation.
- Added three new `GaussErrorCategory` values (`indexing_subscript`, `argument_validation`, `type_mismatch`) and populated the previously-empty `numerical` category for the first time (`G0048`); `matrix_dimension` now has two distinct codes (`G0036`, `G0047`).
- Upgraded `G0290` ("Library not found") from documentation-only to dual-sourced (Real Runtime + Official Documentation) after reproducing it via `library optmum;` against this installation's real, confirmed-absent package; runtime and documentation titles match exactly, no discrepancy. Updated the pre-existing `G0290` tests in `scripts/test_gauss_execution_interpreter.py` and `scripts/test_gauss_execution_diagnostics.py` to assert this new, evidence-driven classification.
- Investigated but did not add `G0117` ("Invalid argument") — its only reproduction was via an indirect, compound trigger too ambiguous to state a non-speculative `known_trigger`. Documented a separate discovered gap: some real GAUSS runtime failures (e.g. `csvRead`'s "file not found" message) are not reported in the `error G####` format this catalog's lookup depends on at all.
- Cause-level diagnostic confidence remains capped at `low` for every catalog-derived cause, including all six new codes — catalog breadth does not raise the confidence ceiling.
- Added `scripts/test_gauss_error_catalog.py` (18 catalog-integrity tests: verification metadata, duplicate/empty-status rejection, documentation-discrepancy retention, dual-sourced vs. real-runtime-only labeling, category validity, no-repair-instruction checks).
- Added 8 new tests to `scripts/test_gauss_execution_interpreter.py`, 9 new tests to `scripts/test_gauss_execution_diagnostics.py`, and 2 new tests to `scripts/test_gauss_code_assistant_cli.py` covering each new code end to end (catalog lookup, interpretation, diagnosis, CLI pass-through) plus regression coverage for the existing five codes.
- Added ten `46.x` Verified Diagnostic Coverage Expansion evaluation run files and updated benchmark coverage, run index, and evaluation dashboard to show 10/10 Passed at 4.0.
- Added `planning/v0.55.0-verified-diagnostic-coverage-expansion.md` and `release-notes-v0.55.0.md`.

- No interpreter or diagnostic-engine control-flow changed; no new CLI command; no execution, workspace, confirmation, or repair-boundary behavior changed.
- Added `v0.54.0` Evidence-Based Diagnostic Reasoning: a new deterministic diagnostic layer (`scripts/gauss_execution_diagnostics.py`) that reasons over execution evidence, interpretation, and the verified GAUSS error catalog to produce a bounded, evidence-only `DiagnosticAssessment` — strictly short of proposing a code repair.
- Added `DiagnosticStatus`/`DiagnosticConfidence` enums and `DiagnosticAssessment`/`DiagnosticCause` dataclasses. Cause-level confidence is capped at `low` for every catalog-derived possible cause, deliberately distinct from (and typically lower than) the underlying error's classification confidence.
- Added `known_triggers`/`diagnostic_questions`/`required_evidence_for_diagnosis` fields to `GaussErrorCatalogEntry`, populated for all five existing codes (`G0105`, `G0036`, `G0025`, `G0014`, `G0290`) from the same accepted evidence sources as each entry's own verification status.
- Added the CLI `diagnose` command, distinct from `interpret`; never calls `execute`/`plan`/`confirm`, never auto-displays stdout/stderr, never auto-reads files, never mutates workspace state, deterministic across repeated calls.
- Added a fixed repair-boundary disclosure ("Diagnosis does not modify or repair the program.") present in every diagnostic branch; `DiagnosticAssessment` has no field capable of holding replacement code.
