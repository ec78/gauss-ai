# v0.4.0 Retrieval Prototype Plan

## Release Goal

Build a lightweight, local-first retrieval prototype that helps the GAUSS Code Assistant locate official GAUSS command-specific documentation when exact syntax, defaults, return values, options, or examples are needed.

## Scope

- Discover local official GAUSS documentation sources.
- Look up command-specific documentation from local `.rst` files.
- Extract source-aware syntax and usage notes without mirroring full documentation pages.
- Distinguish official documentation, curated notes, command categories, and unresolved retrieval gaps.
- Support a minimal prototype that can be reviewed and tested before broader indexing work.

## Non-Goals

- Full semantic search.
- GAUSS runtime execution.
- Indexing every GAUSS command.
- Public hosted search service.
- Replacement of official GAUSS documentation.
- Large copied command documentation cache.

## Required Deliverables

- Tool design for command documentation lookup.
- Implementation plan for a small local docs lookup script.
- Retrieval-focused benchmark prompts.
- Coverage tracker entries for retrieval benchmarks.
- Updated roadmap and changelog entries for `v0.4.0`.

## Suggested Implementation Stages

1. Validate local docs source resolution from shared and local knowledge-source config.
2. Build a narrow command-page lookup for one command name and a local docs root.
3. Extract headings, syntax blocks, documented inputs, outputs, examples, and caveats from matched `.rst` files.
4. Return source-aware results with confidence and unresolved questions.
5. Test against a small command set before considering wider indexing.
6. Integrate retrieval results into Code Assistant response guidance.

## Initial Commands To Test Retrieval With

- `olsmt`: high-value statistical workflow command with existing benchmark pressure.
- `strindx`: failure-prone string command with known not-found behavior.
- One command discovered only from `COMMAND_CATEGORIES.md`: used to test category discovery followed by command-specific lookup failure or ambiguity handling.

## Risks

- Treating category membership as proof of exact syntax.
- Extracting too much official documentation into this repository.
- Overstating retrieval confidence when `.rst` matches are ambiguous.
- Returning stale curated notes as if they override official docs.
- Building a larger search system before the narrow lookup behavior is validated.

## Open Questions

- What is the canonical local docs root layout for supported GAUSS documentation checkouts?
- Should lookup accept command aliases or only exact command names at first?
- How should the prototype distinguish base GAUSS commands from package-specific commands?
- What minimum source citation should be returned with each match?
- How should version metadata be detected when docs roots include multiple GAUSS versions?

## Evaluation Plan

- Add retrieval benchmarks for `olsmt`, `strindx`, and category-only command discovery.
- Manually evaluate whether responses distinguish verified syntax from unresolved behavior.
- Confirm that retrieval failures are explicit and do not lead to invented syntax.
- Compare curated notes against official docs when both are available.
- Keep new retrieval benchmarks marked `Not Run` until the prototype or manual retrieval workflow is exercised.
