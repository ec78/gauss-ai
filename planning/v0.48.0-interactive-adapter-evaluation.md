# v0.48.0 Interactive Adapter Evaluation and Alpha Readiness

## Release Goal

Evaluate the `v0.47.0` Interactive MVP Adapter as a real terminal alpha harness, complete the `41.x` benchmark category, and decide whether structured human alpha testing can begin.

This is an evaluation and readiness milestone. It does not implement durable `ExecutionSession` integration, real GAUSS execution, a chat adapter, uploads, persistence, or broader product features.

## Evaluation Method

The evaluation exercised `scripts/gauss_code_assistant_cli.py` through `InteractiveMvpAdapter.handle_line(...)`, using disposable temporary workspaces and the adapter's deterministic fake runner. The observed path was:

```text
terminal-like command
  -> InteractiveMvpAdapter.handle_line(...)
  -> GaussCodeAssistantWorkflow
  -> ExecutionWorkflow / WorkspaceRegistry / WorkspaceFileReader
  -> deterministic fake runner for execute
```

No benchmark was passed merely because a unit test exists. Each `41.x` run file records observed adapter behavior, identifiers shown, confirmation behavior, workspace behavior, output/read behavior, disclosure quality, and defect severity.

## Transcript Coverage

Completed transcript scenarios:

- Successful alpha flow: `workspace create -> request -> plan -> confirm -> execute -> outputs -> read -> provenance -> status -> exit`.
- Blocked execution: `execute` before confirmation returned `MvpWorkflowStageError`; no runner invocation occurred.
- Stale confirmation: confirming an old hash after replacing the request returned `ConfirmationValidationError`; no execution occurred.
- Decline and recovery: `decline` cancelled the proposal, blocked later execution, and a fresh request/proposal/confirmation succeeded in the same still-ready workspace.
- Fake failure and recovery: deterministic fake failure reported `execution_status: failed`, `runtime_error_detected: True`, no output artifacts, then a fresh workspace completed a successful fake run.
- File safety: pre-output read returned `file_not_found`, path traversal returned `path_escapes_workspace`, absolute path returned `path_not_relative`, `outputs` reported metadata only, and explicit `read fake-output.txt` returned content.

## Benchmark Results

`41.1` through `41.10` all passed at `4.0`.

- Critical defects: 0.
- Major defects: 0.
- Minor defects: 0.
- Implementation fixes: none.
- GAUSS invocations: 0.

## Alpha-Readiness Decision

Classification: **Ready for structured manual alpha testing**.

Rationale:

- A human can launch the adapter from a terminal and complete the main workflow without writing Python.
- The adapter visibly reaches the real MVP workflow facade and workspace/file-reader layers.
- Execution remains blocked until a hash-bound confirmation is accepted.
- Stale or mismatched confirmation is rejected by the existing workflow validation path.
- Output metadata is reported without reading file contents.
- File content is returned only after an explicit `read` command.
- Workspace path boundaries hold for traversal and absolute outside-workspace reads.
- Fake execution is consistently disclosed as fake, and status reports `gauss_ran: false`.
- Provenance is reported without pretending the orchestration-instance alias is a durable `ExecutionSession`.

## Current Limitations

- Adapter execution is fake-runner-only.
- CLI state is local and process-scoped.
- Request interpretation is intentionally limited and adapter-driven.
- `WorkflowResult.execution_session_reference` still means `orchestration_instance_id`, not a durable `ExecutionSession` ID.
- A completed workspace remains single-shot for execution; use `workspace create` for another execution after completion.
- The adapter is a terminal harness, not a Claude Code/Codex chat adapter.

## Recommended Next Step

Pause broader development and run structured manual alpha tests using `docs/manual-alpha-testing-guide.md` and `docs/alpha-feedback-template.md`. Use alpha feedback to prioritize the next milestone rather than defaulting immediately to durable session integration.
