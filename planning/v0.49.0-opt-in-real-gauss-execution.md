# v0.49.0 - Opt-In Real GAUSS Execution

## Goal

Connect the Interactive MVP Adapter to the existing verified GAUSS execution helper so a manual alpha tester can explicitly choose real local GAUSS execution from the terminal.

The default remains the deterministic fake runner. Real execution is never automatic and never selected because GAUSS happens to be installed.

## User Problem Solved

After `v0.48.0`, testers could exercise the real MVP workflow end to end, but every execution result came from a fake runner. That made the adapter manually testable, but not able to answer the next alpha question: "Can this terminal MVP path actually run local GAUSS when I explicitly ask it to?"

`v0.49.0` provides that smallest bridge.

## Scope

Implemented:

- `scripts/gauss_code_assistant_cli.py` accepts `--runner fake|gauss`.
- Fake runner remains the default.
- Real runner mode requires `--gauss-executable` or `GAUSS_EXECUTABLE`.
- CLI argument path takes precedence over `GAUSS_EXECUTABLE`.
- Real runner startup validates that the path exists and is named `tgauss` or `tgauss.exe`.
- Real runner mode lazily imports and calls the existing `gauss_code_execution.execute_gauss_code(...)` helper.
- No shell command string is built by the CLI; execution remains inside the helper's existing structured boundary.
- No silent fallback from real mode to fake mode exists.
- Plan output discloses backend, executable, workspace, timeout, request hash, and the inline-code/generated-script boundary.
- Execute output discloses backend, `gauss_ran`, exit code, timeout state, duration, stdout/stderr lengths, generated script path, and output metadata without printing stdout/stderr or output-file contents.
- Provenance and status output disclose selected backend and whether a GAUSS process was reported as started.
- `scripts/test_gauss_code_assistant_real_runner.py` covers the real-runner adapter boundary with injected helpers by default and includes an explicit `--run-gauss` smoke gate for local manual verification.

Explicitly excluded:

- Durable `ExecutionSession` integration.
- Claude Code/Codex chat adapter integration.
- Cloud execution.
- Upload handling.
- Autonomous execution, retry, repair, or file reading.
- General shell command execution.
- GUI GAUSS executable support.
- Cross-platform/cross-version claims beyond the repository's existing verified evidence.

## Safety Boundaries

- Real execution requires an explicit backend selection.
- Real execution requires a real terminal executable path.
- Existing hash-bound confirmation is still required before `execute`.
- Missing/invalid executable paths block startup in real mode.
- Real-runner helper failures do not fall back to fake execution.
- `gauss_ran=true` is reported only when the helper result reports `executed=true`.
- Output file contents remain behind the existing explicit `read <relative-path>` command.
- Stdout/stderr contents are captured by the helper but not printed automatically by the adapter.
- Execution success remains separate from GAUSS syntax generality and statistical/methodological validity.

## Validation

Default validation should not run GAUSS:

```text
python scripts/test_gauss_code_assistant_cli.py
python scripts/test_gauss_code_assistant_real_runner.py
```

Optional local real smoke test, only after default validation passes:

```text
python scripts/test_gauss_code_assistant_real_runner.py --run-gauss --gauss-executable C:\gauss26\tgauss.exe
```

The optional smoke test is intentionally not part of the default release-health path because it depends on a local GAUSS installation.

For this milestone implementation, the optional smoke command above was run against `C:\gauss26\tgauss.exe` after all non-GAUSS validation passed, and the harness reported `PASS optional real GAUSS smoke test`.

## Remaining Limitations

- The interactive adapter is still process-local.
- The MVP facade still does not use durable `ExecutionSession` records.
- Inline-code script path is generated by `gauss_code_execution` at execution time, so the plan discloses the generated-script boundary before confirmation and the exact generated path after execution.
- Real execution evidence is still bounded by the helper's existing Windows/GAUSS 26.x verification history.
- A non-developer still needs terminal instructions and a local GAUSS executable path to use real mode.
- Claude Code or Codex will not automatically invoke this adapter without a separate harness or explicit command execution.
