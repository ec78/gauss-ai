## Verified Runtime-Error Summary

### Undefined Symbol

**Script:**

```gauss
print undefinedvar;
```

**Observed:**

- Exited non-interactively.
- No timeout.
- stdout empty.
- stderr included `error G0025 : Undefined symbol: 'undefinedvar'`.
- `exit_code: 0`.
- No lingering GAUSS process.

### Dimension Mismatch

**Script:**

```gauss
x = ones(2,2);
y = ones(3,3);
z = x + y;
print z;
```

**Observed:**

- Exited non-interactively.
- No timeout.
- stdout included `Program execute failed`.
- stderr included `error G0036 : Matrix dimensions are incompatible`.
- `exit_code: 0`.
- No lingering GAUSS process.

**These findings confirm that the existing error-detection heuristic covers the two tested runtime-error types, because both surfaced the observed `error G####` pattern and/or `Program execute failed`.**

## Exit-Code Caveat

`v0.29.0` reinforces the `v0.28.0` finding that GAUSS exit codes are not sufficient for success/failure classification.

GAUSS returned `exit_code: 0` for:

- Successful output-file execution.
- Undefined-symbol runtime error.
- Dimension-mismatch runtime error.
- The prior syntax-error case from `v0.28.0`.

**Therefore:**

- `exit_code: 0` cannot prove success.
- Error-output detection remains required.
- `completed` execution cannot be inferred from `exit_code` alone.
- Helper status classification must continue to treat detected GAUSS error output as `failed` even when `exit_code` is `0`.
