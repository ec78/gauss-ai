# v0.12.0 GAUSS Language Knowledge Cleanup and CI Guard Prep Plan

## Release Goal

`v0.11.0` cleaned up documentation and evaluation-policy drift, but left two of its own follow-ups open, and neither of the two local guard scripts (`scripts/validate_all_evidence.py`, `scripts/check_evaluation_tracking.py`) has ever been packaged into a single release-check entry point or documented for eventual CI use. `v0.12.0` continues the same cleanup/policy-hardening posture rather than adding capability: it clarifies the GAUSS Language Expert's `knowledge.md` placeholder (the direct parallel to `v0.11.0`'s Econometrics fix), improves release-check ergonomics with a small wrapper script that runs the existing default guards in one command, documents current strict-mode behavior clearly enough that a future CI setup could reuse it without guessing, and documents how the `PACKAGE_DOC_DIRECTORIES` snapshot should be refreshed. Runtime behavior is unchanged throughout: no validator logic changes, no warnings are suppressed or hidden, and no CI workflow is added in this milestone.

## Current State

- Evidence validation (`scripts/validate_all_evidence.py`) default run passes: 14 files checked, 0 unexpected, 6 total warnings. `--strict` intentionally fails on exactly 2 files — `glm.evidence.json` and `olsmt.evidence.json` — both due to reviewed HDF5-URI path-warning false positives from official documentation examples, not real path leaks.
- Evaluation tracking (`scripts/check_evaluation_tracking.py`) default run passes: 71 prompt IDs, 71 coverage rows, 58 run files referenced, 63 index entries checked, 0 errors, 2 warnings. `--strict` intentionally fails on the same 2 documented historical warnings (the `2.2`/`2.3` Prompt ID mismatch, and the unindexed `v0.3.0` smoke-test file).
- `experts/econometrics/knowledge.md` is now a compatibility placeholder (`v0.11.0`) pointing to `experts/econometrics/BODY_OF_KNOWLEDGE.md`, with a repo-wide reference check confirming nothing else depends on its prior placeholder content.
- `experts/gauss-language/knowledge.md` still appears to be the identical one-line placeholder ("Placeholder for domain knowledge notes.") that `experts/econometrics/knowledge.md` was before `v0.11.0` — confirmed by direct read during `v0.11.0`'s own audit, flagged there as an explicitly out-of-scope follow-up.
- Package source classification (`scripts/command_doc_lookup.py`, added `v0.11.0`) uses a hardcoded `PACKAGE_DOC_DIRECTORIES` constant derived from the official GAUSS Applications index (`docs_root/applications.rst`), not live-parsed — documented as a maintained snapshot that should be refreshed if that index changes, but the refresh *process* itself has not been written down anywhere yet.
- No single command runs "the release-health checks" together; a release reviewer currently has to know to run both `validate_all_evidence.py` and `check_evaluation_tracking.py` separately, and there is a stale, `v0.2.0`-specific `RELEASE_CHECKLIST.md` at the repo root that has not been touched since that milestone.
- No CI workflow exists for either guard script; both remain local, manually-run tools.

- No new operational expert.
- No runtime orchestration.
