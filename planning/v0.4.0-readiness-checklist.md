# v0.4.0 Readiness Checklist

This checklist audits whether the repository is close to tagging `v0.4.0` - Retrieval Prototype. It is an audit record only; it does not tag a release.

## 1. Release Goal

`v0.4.0` is intended to prove:

- The GAUSS Code Assistant can use local official documentation lookup evidence to answer command-specific questions (exact syntax, defaults, control options, return structure, intercept/formula/not-found behavior) more safely than relying on category membership or general knowledge alone.
- The retrieval prototype is local-first and intentionally limited: it searches a local official docs checkout with a small heuristic script, not a hosted or semantic search system, and does not replace official GAUSS documentation.

It is not intended to prove that retrieval is complete, automated end-to-end in the assistant runtime, or validated across more than a small pilot set of commands.

## 3. Evaluation Evidence

- **Prompt 11.1** (`olsmt` syntax and intercept behavior) — Pass, 3.8. The assistant used `COMMAND_CATEGORIES.md` only for discovery, then verified exact `olsmt` syntax, the formula string's `-1` no-intercept behavior, and `ctl.con`'s default-`1` behavior directly from `examples/retrieval/olsmt.lookup.json`, rather than deferring to the user.
- **Prompt 11.2** (`strindx` not-found behavior) — Pass, 3.75. The assistant verified from `examples/retrieval/strindx.lookup.json` that `strindx` returns `0` when no occurrence is found, explicitly contrasted this with Python `.find()`'s `-1`, and used a GAUSS-safe `idx == 0` example.
- **Prompt 11.3** (category-only command candidate) — Pass, 4.0. The assistant confirmed it will not infer exact syntax, arguments, defaults, or return fields from category membership alone, and instead recommended a concrete retrieval next step (`scripts/command_doc_lookup.py <command> --docs-root <docs-root>`).

All three retrieval benchmarks pass with no automatic failure conditions triggered in any run.

## 4. Remaining Limitations

- Retrieval is local-only: it requires a local checkout of official GAUSS documentation and does not fetch or host documentation itself.
- The lookup script is heuristic (heading/underline pattern matching, `.. function::` directive parsing, keyword substring search), not a full reStructuredText parser — it can misparse unusual formatting.
- Extraction may truncate long sections (observed directly: `olsmt`'s `outputs_section`/`controls_section` are truncated mid-field in the committed example, so not all `olsmtOut` members are verified).
- Keyword hits can miss conceptually relevant text if the wording differs from the literal keyword (observed directly: `strindx`'s doc describes not-found behavior as "no occurrence is found" rather than the literal phrase "not found," so a keyword search for `"not found"` returns zero hits despite the behavior being documented and verified elsewhere in the same extraction).
- Only a small pilot set of commands has been tested end-to-end (`olsmt`, `strindx`); broader command coverage is unverified.
- The system does not execute GAUSS code; nothing in the retrieval prototype runs or validates GAUSS syntax at runtime.
- Official GAUSS documentation remains authoritative over any extracted summary, curated note, or evaluation response produced by this prototype.

### Non-Blocking Follow-Ups

- Add a validation-step suggestion (e.g., compare `olsmt`'s `out.b` against R's `coef(model)`) to strengthen 11.1-style translation responses.
- Add a found-case example alongside the not-found example for `strindx`.
- Add a short curated `strindx` command note in `experts/gauss-language/commands/`, similar to the existing `olsmt.md` note.
- Improve extraction so the full `olsmtOut` field list is captured instead of truncating after `out.b`.
- Add more command lookup examples beyond `olsmt` and `strindx` to widen pilot coverage.
- Consider genericizing the example docs-root path shown in `scripts/README.md` and `examples/retrieval/README.md` to a placeholder rather than a specific local path.

## 6. Readiness Decision

**Decision: Ready.**

Rationale: every required deliverable exists and is current, including the now-updated `KNOWN_LIMITATIONS.md`. All three retrieval benchmarks pass with real (not fabricated) evidence, tracking files (`CHANGELOG.md`, `ROADMAP.md`, `INDEX.md`, `benchmark-coverage.md`) are current, both generated lookup JSON files are free of unredacted local paths, and no release tag has been created prematurely. No blockers remain. The non-blocking follow-ups below are reasonable to defer to `v0.5.0` or later without weakening the "prototype, not production retrieval" framing.
