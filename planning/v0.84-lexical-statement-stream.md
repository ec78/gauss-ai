# v0.84.0 — One Lexical Statement Stream: Design

Status: **implemented and tagged `v0.84.0`** (2026-10-13; not pushed at time of writing). The plan (§1–§8) was approved on 2026-10-13 with every recommendation in §8. §9 records what changed during implementation and the verdict diff; §10 is testing. Live evaluation `74.x` (§7) has not been run.

## 1. Why

Live evaluation 73.x (`planning/v0.83-verdict-explanations-and-search-recall.md` §11.5) found two real validator defects. Both come from scans of GAUSS source that ignore its lexical structure:

| Finding | Seen in | Effect |
|---|---|---|
| 1. String contents are scanned for assignment and `proc` targets | 73.14 | `print "det = " d;` makes `det(x)` a variable: a false not_ready. A `"fakeinverse = "` label hides a hallucinated call from `unknown_symbols`: not_ready softens to review_required. Both paths (`validate_code`, and `check_generated_symbols` on `ask()`). |
| 2. Statements are cut at newlines before `;` | 73.10 | `_governing_assignment` never sees a multi-line matrix literal. A known two-line `invpd` SPD violation drops from not_ready to review_required. |
| 3. `coverage_gaps` is silent for undocumented calls | 73.14 | A `partial` signature check is left with an empty gap list. |

Reproducing these and inventorying every scan (§2) found **a worse instance of the same class, not seen live.** Text inside string literals can hide a `dos dir;` statement from the system-statement scan, and the snippet reaches **handoff_candidate** (§2.2). This violates the CLAUDE.md constraint that code reaching outside GAUSS's memory is always `NOT_READY`. A `validation_id` is still only usable through the operator opt-in plus explicit, digest-bound human approval. But the deterministic verdict is wrong in the unsafe direction. The defect predates v0.83.0: the comment stripper dates from v0.74.0, and the quote regex from v0.76.0.

Goals:
- one shared lexer and one string-masked, `;`-terminated statement stream that keeps exact line and column numbers. Every scan of GAUSS source in the two validator modules reads it; no per-site patches;
- every 73.10/73.14 probe reaches the verdict its evidence supports;
- every partial verdict names its cause, including undocumented calls.

Constraints:
- no change to `_SYSTEM_STATEMENT_REGISTRY`, the readiness state machine (`compute_handoff_readiness`'s state logic), `compute_eligibility`'s verdict logic or `compute_evidence_profile`;
- no change to documentation extraction (so no all-pages diff; §6.3);
- `ground_multi`, `resolve_concepts`, `compute_generation_gate` and the concept index are untouched (§6.4).

Out of scope (from the brief): expression category inference (72.3 finding 1) and public release readiness.

### 2.4 Finding 3: why `coverage_gaps` is empty

`compute_coverage_gaps` (`:3426`) emits signature gaps only for `cv.documented and not cv.signature_known`. An undocumented call (`documented=False`) makes `signature_check` partial through `compute_validation_coverage` but produces no gap. Normally such a call is also in `unknown_symbols` (a not_ready blocker), so the hole shows only when finding 1 hides it. After the fix it still shows legitimately: for a call to a `proc` defined in the snippet, which is user-defined, so it is not unknown and not documented.

### 2.5 Optional item (4): sized, and not small

- **73.12 (`sortc`).** "sort a matrix by a column" resolves as ambiguous between `sortmc` and `sortr`/`sortrc` (2 keywords each). `sortc`'s keywords are `sortc, sort, dataframe`, a 1-keyword overlap. Mode B lists only the top overlap tier and never runs alongside mode A. Offering `sortc` needs a new candidate rule, not a constant.
- **73.13 ("percentile").**
  - "percentile" is a keyword only of `box`/`plotBox`.
  - "compute percentiles of a vector" partially grounds on `vectordl.rst` through "vector", and candidates are suppressed whenever sources exist.
  - Reaching `quantile` needs either a curated synonym or candidates on partially grounded queries.
- **New, worse:** "how do I compute the 95th percentile of a column" is **`grounded`, policy `full`, on `setColDateFormats`**.
  - That page's derived keywords include `how` (from "Specifies **how** GAUSS should display dates") and `column`, which reaches `MIN_KEYWORD_OVERLAP` = 2.
  - So `ask()` would generate code grounded on a date-format page.
  - The leak is narrow: of 1,845 index entries, `how` is a keyword of 1 and `what` of 1.

A candidate-only patch would fix 73.12/73.13 cosmetically while leaving the false full grounding. **Recommendation: exclude (4) from v0.84.0** (§8 decision 8). Record the `setColDateFormats` finding, and give search/grounding quality its own milestone, where gate changes are intended and diffed.

## 3. Proposed design

Deterministic, stdlib-only, in `gauss_pre_execution_validation.py`. It already owns `_QUOTED_STRING_RE`, `_split_statements` and `call_scan_text`, and the engine and the differential harness already import it, so no new module and no `pyproject.toml` change is needed. Public names, so no module reaches into another's private helpers.

### 3.1 The lexer: `lex_gauss_source(code) -> LexedSource`

A single left-to-right state machine. Each transition is backed by a §2.2 spot check:

| State | Enter on | Leave on | Ignores inside |
|---|---|---|---|
| code | — | `"` → string; `//` → line comment; `/*` → block comment (depth 1); `@` → at-comment | — |
| string | `"` | an unescaped `"`; `\` consumes the next character, any character (t2, a10, u4) | `//`, `/*`, `@`, `;`, newlines (a5, t1, t3, a2) |
| line comment | `//` | newline (kept) | everything (a6) |
| block comment | `/*` | the `*/` that brings the depth to 0; each nested `/*` increments it (t6) | `"`, `//`, `@` (a4, u3, a8) |
| at-comment | `@` | the next `@` (t7, a1, a9) | `"`, `//`, `/*` (a7) |

`LexedSource` (frozen) carries:
- `code_view`: the same length as the input, with comments replaced by spaces and **newlines kept**. String text is intact. It replaces C1, so argument text (for example `"%d"`) is still sliced from real code.
- `masked_view`: `code_view` with every string token, quotes included, replaced by `#` and newlines kept. It replaces P7 and is what every structural scan reads.
- `string_spans`, `comment_spans` (each with kind `line`/`block`/`nested_block`/`at`), and `unterminated` (`string`/`block_comment`/`at_comment` at end of input, else `None`).

Because both views preserve length, any offset maps to the exact `(line, column)` of the original text. That also fixes the block-comment line shift.

`_strip_comments_for_analysis(code)` stays as a thin wrapper returning `lex_gauss_source(code).code_view`, so its six call sites are unchanged. Lexing is idempotent on `code_view`, so downstream functions re-lex what they receive. The differential harness's copy is replaced by a call to the public lexer (§8 decision 10).

### 3.2 The statement stream: `source_statements(lexed) -> tuple[SourceStatement, ...]`

`masked_view` is split on `;` across lines, as `_split_statements` does today. Each `SourceStatement` (frozen) has:
- `start` and `end` (offsets);
- `line` and `column` of its first non-space character;
- `end_line` and `end_column` of its terminating `;`, or of end of input;
- `masked` (the statement's masked text) and `text` (the same span of `code_view`, strings intact);
- `terminated`.

`_split_statements` and `_masked_statements` both become views of this stream:
- `_split_statements` keeps its `_Statement` shape for the control-flow and `let` checks;
- `_masked_statements` is removed, and its one caller (P5) moves to the stream.

### 3.3 Consumers moved onto the stream

| Site | Change |
|---|---|
| C1 | `_strip_comments_for_analysis` → `code_view` (§3.1) |
| C2–C4 | one shared `collect_user_defined_symbols(statements) -> frozenset[str]`, used by both `validate_code` and `check_generated_symbols`. It collects two kinds of name. (a) A **statement-leading** assignment target: the identifier immediately before the statement's first top-level `=` (not `==`, `!=`, `<=`, `>=`, `.==` …), when everything before it is bare identifiers. That covers `x =`, `let x =`, `string s =` and `struct DS s =`, and excludes `s.x =`, `x[1] =` and `{a, b} =`. Statements led by `if`/`elseif`/`while`/`until`/`for` are excluded. (b) The name after a statement-leading `proc` (`proc (1) = name(` / `proc name(`). It reads `masked`, so string contents are never seen. |
| P1, C5 | `call_scan_text(line)` → `call_scan_view(lexed, statements)`: `masked_view` with **declaration statements** (leading `proc`/`endp`/`local`) blanked statement by statement, not line by line, and each `for`/`threadfor` header's counter blanked. One shared definition, as in v0.80.0. `call_scan_text` is kept as a per-line wrapper only if a test still needs it. |
| P2 | `extract_generated_calls` scans `call_scan_view` as one text. Parentheses are matched across newlines. `line_number`/`column` come from the name's offset. Argument text is sliced from `code_view`. |
| P3 | splitting runs on the masked slice and maps the spans back to `code_view`, so escaped quotes and commas inside strings never split an argument |
| P4, P5 | `_governing_assignment` iterates `source_statements`. "Ends before the call" compares `(end_line, end_column)` with the call's `(line_number, column)`. The block-depth, refusal and option-B logic is unchanged, and the returned right-hand side is the statement's `text` after `=` (it may span lines, which P6 already accepts) |
| P7–P12 | `validate_syntax` reads `masked_view` throughout. `_check_matrix_literals` moves to masked text (P9). `call_found`/`string_found` use masked text and `string_spans` (P11). The `_QUOTED_STRING_RE` masking is retired from validator paths. |
| P10 | `unterminated_string` becomes lexer-based and escape-aware. The rule fires for a string still open at end of input; what happens to a string that spans a newline is decision 5. |
| P13 | `check_system_statements` iterates the lines of `masked_view` instead of re-masking each raw line with P7. **The anchors (`_SYSTEM_STATEMENT_RE`, `_SYSTEM_CALL_RE`, `_INCLUDE_DIRECTIVE_RE`) and the registry are unchanged.** Line starts remain statement starts (still a superset), so the only behavioral change is correct masking. |
| P14 | inherits P2/P5 |

New syntax handling, only from the lexer's own evidence:
- **`unterminated_block_comment`** → INVALID (u2, `G0562`), and **`unterminated_at_comment`** → INVALID (u1, `G0008`). These are new `_SYNTAX_RULE_REGISTRY` entries with the spot-check provenance. They are computed from the raw block in `validate_generated_code` (`code_view` has already blanked the comment), and so apply to both paths.
- `@` comments and nested `/* */` are masked exactly as GAUSS treats them. Under decision 3 they also add an unknown construct `undocumented_comment_form` (syntax `partial`, at best review_required).

### 3.4 Finding 3: undocumented calls in `coverage_gaps`

`compute_coverage_gaps` adds one entry per distinct `cv.symbol` with `not cv.documented`:
- check `signature`, cause `call_undocumented`;
- detail: "no documentation was found for `name`, so its call signature cannot be checked. A procedure defined in this snippet is never checked against documentation."

`compute_handoff_readiness`'s signature reason names these symbols the same way v0.83.0 names role gaps. The state logic is untouched; this is wording only.

### 3.5 What does not change

- `_SYSTEM_STATEMENT_REGISTRY` and the system-scan anchors.
- `compute_handoff_readiness`'s states, `compute_eligibility`'s verdict logic and `compute_evidence_profile`.
- `RoleUnknownCause`'s values. 73.10's wrong `argument_assigned_from_expression` label disappears because the literal is now traced, not because the label changes.
- Documentation extraction, and every search/grounding function (§6.4).
- No expression is ever evaluated.

## 4. Scope boundary

In scope: §3.1–§3.4. Every C/P site in §2.3. The differential harness's stripper (decision 10).

Out of scope:
- **Item (4)**, if decision 8 follows the recommendation, plus the new `setColDateFormats` false-grounding finding (§2.5). Both are recorded for a search/grounding milestone.
- **Expression category inference** (72.3 finding 1).
- **`fn` one-line functions and `keyword` procedures** as user-defined names. Today `fn area(r) = …; area(2)` reports `area` unknown, a false not_ready in the safe direction.
- **Multi-target assignment** (`{a, b} = f(x)`) targets as user-defined. They are not collected today either, which is the safe direction.
- **Reserved-word knowledge** (t5: `det = 3` is `G0276`).
- **Preprocessor blocks** (`#ifdef`). The validator sees all branches, which is over-reporting and fails closed.
- **Public release readiness.**

## 5. Known limitations this design accepts

To be disclosed in `KNOWN_LIMITATIONS.md` (the 73.x findings also go there; `PROJECT_STATUS.md` notes they are still missing):
- The lexer is a lexer, not a parser. Statement boundaries are `;` outside strings and comments, which is exactly GAUSS's rule. Statement *meaning* is still read through the bounded rules.
- `@` comments and nested block comments are modelled from spot checks (t6, t7, a1, a7–a9), not from the published docs, which never mention `@`. Under decision 3 they cap the verdict at review_required.
- Under decision 5's recommendation, a string literal that spans a newline (legal, a5) is an unknown construct, not a candidate.
- A statement-leading target rule can still be fooled by a real assignment to a hallucinated name followed by a call to it (`fakefn = 1; y = fakefn(x);`). In GAUSS that is indexing a variable, so the call shape is not a function call. This is unchanged and correct.
- A call to a `proc` defined in the snippet stays review_required with a named `call_undocumented` gap (`proc` blocks are already a `control_flow_block`).

## 8. Decisions needed

1. **Scope: include the §2.2 unsafe rows** (string-embedded `/*…*/` and `\"` escapes hiding `dos`, reaching handoff_candidate). *Recommend yes.* They are the same lexical defect, the shared lexer fixes them by construction, and leaving them would break a CLAUDE.md constraint.

3. **`@` comments and nested `/* */`.** Mask them as GAUSS does (t6, t7) **and** add the unknown construct `undocumented_comment_form`, so such code is review_required at best. *Recommend yes.* `@` is undocumented in the published docs. 4. **Unterminated block and `@` comments → INVALID** (new rules, `G0562`/`G0008` provenance). *Recommend yes.* Without them, an unterminated `/*` would silently mask the rest of the snippet.
5. **A string literal spanning a newline** (legal per a5).
   - Option (a): keep it INVALID, the current per-line behavior made escape-aware.
   - Option (b): an unknown construct (review_required at best).
   - Option (c): accept it.

   *Recommend (b).* INVALID claims a violation GAUSS does not have, and (c) adds candidacy for a form models rarely write.
6. **User-defined targets: statement-leading only** (§3.3 C2–C4), which drops member writes such as `s.fakefn =`. *Recommend yes.*
7. **Finding 3 wording:** gap cause `call_undocumented`, with the readiness reason naming the symbol. *Recommend yes.*
8. **Item (4): exclude** and record the new `setColDateFormats` false-full-grounding finding (§2.5) for a separate search/grounding milestone, where gate changes are intentional. *Recommend exclude.* It is not small. Its sharpest defect needs a gate change, which the brief rules out for this item.

### 9.1 As planned

- **Lexer** (`gauss_pre_execution_validation.py`):

### 9.2 Deviations

1. **`validate_syntax` takes the raw block.** §3.3 planned computing the comment rules separately from the raw block in `validate_generated_code`. Simpler and equivalent: `validate_syntax` lexes whatever it is given (lexing is idempotent on comment-stripped text), so `validate_generated_code` and the differential harness now pass the raw block. The comment rules see the comments, and every other rule reads the same masked view as before.
2. **`call_scan_text` is removed**, not kept as a per-line wrapper. No test called it.
3. **`_split_top_level_args` is unchanged.** It also parses *documented* signatures, and §1 rules out extraction changes. Code arguments use the new `_split_masked_args`. The AST comparison below confirms every extraction function is byte-identical to HEAD.
4. **Caching.** `lex_gauss_source`, `source_statements`, `call_scan_view` and `collect_user_defined_symbols` are `functools.lru_cache`d (128 entries; immutable results). The tracers re-ask per argument, so the cache stops the same snippet being re-lexed repeatedly. Lexing a 19,000-character snippet cold takes 10 ms.
5. **A traced right-hand side is quoted on one line in reasons.** It can now span lines; the whitespace is collapsed only in the explanation text.
6. **`unterminated_string`'s message still contains "not closed"** ("…is not closed before the end of the code"), so test 84 needed no change. No existing test expectation was updated.
7. **`_governing_assignment` reads the leading word with `_leading_word`** rather than `_starts_with_keyword`, because a block keyword followed by a newline (`if`⏎`x > 1;`) is a whole statement now. The `clear` refusal regex gained `re.DOTALL` for the same reason.
8. **Not anticipated: `dos` inside an unterminated `/*` is no longer listed as a system statement.** The verdict stays not_ready, now from `unterminated_block_comment`. This matches real GAUSS: `G0562`, so nothing in the file runs. (A5 "unterminated block comment".)
