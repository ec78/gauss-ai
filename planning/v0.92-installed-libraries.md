# v0.92.0 — Installed Libraries: Design

Status: **implemented** (2026-11-06). Approved: decision 1 = (b) as applied in §8.1, decisions 2-5 = yes. Implementation, deviations and diffs: §9-§11. Live evaluation 83.x: §12 (10 pass, 1 fail). `v0.92.1` (package structure types): §13. Baseline for every probe and comparison: `v0.91.1` (`696259d`), the docs copy fetched on 2026-10-23, and this machine's GAUSS 26.1.4 at `C:\gauss26`.

The third milestone under v0.89's decision 10 = **B** (widen deterministic coverage). It takes up the item the user agreed to on 2026-10-29 (`planning/v0.91-expression-categories.md`, revision note and §2.4): allow `library <name>;` for an Aptech-documented package installed in the configured GAUSS, with each called function confirmed in the installed index. That is a sign-off to relax CLAUDE.md's source-inclusion rule **for that shape only**; everything else that reaches outside GAUSS's memory stays `not_ready`.

## 1. Why

- **Package code cannot run through gauss-ai.** `library` is always `source_inclusion` (`not_ready`). Live 82.13's lasso program (`library gml;`, `trainTestSplit`, `lassoFit`, `lmPredict`) is correct and runs in GAUSS, but could not reach a prompt. Package pages hold 238 of the 1,449 extracted signatures (v0.91 §2.4): GML, `timeseries`/`tsmt`, `tspdlib`, `cmlmt` and others, which is most of what a full analysis workflow needs.
- **The reverse gap is a real defect.** A package function called *without* its `library` line can reach `handoff_candidate` and then fail with `G0025` (pre-existing; 44 single-form package functions at `v0.89.2`; `KNOWN_LIMITATIONS.md` since v0.90.0).
- **A client had to use the shell to learn what is installed** (82.12: `Test-Path C:\gauss26\pkgs\gml`).

## 2. Evidence

All spot checks ran with `tgauss.exe -b` (GAUSS 26.1.4) from new empty scratch directories on 2026-11-06.

### 2.1 Which index `library <name>;` loads

`gauss.cfg` sets `lib_path = $(GAUSSDIR)\lib` and `extra_lib_path = $(GAUSSDIR)\gaussplot\lib;$(PACKAGEDIR)\*\lib`, with `PACKAGEDIR = $(GAUSSDIR)\pkgs`. GAUSS's own `library;` listing (lb01, lb03) shows the search order: `gaussplot\lib`, then each `pkgs\*\lib` in alphabetical order, then `lib`. The first `<name>.lcg` found wins.

**This explains v0.91 §2.4's two unexplained `G0025`s.** `pkgs\timeseries\lib` contains its own `tsmt.lcg`, a "backward-compatibility alias" generated by Aptech, and `timeseries` sorts before `tsmt`. So `library tsmt;` loads `pkgs\timeseries\lib\tsmt.lcg` (lb01: "Libraries: … `pkgs\timeseries\lib\tsmt.lcg`"), never the legacy `pkgs\tsmt\lib\tsmt.lcg`. `adjRsq` and `chowfcst` are only in the legacy index, so both are `G0025` after `library tsmt;` (lb02, lb07). The "legacy `tsmt` build without `adjRsq`" in v0.91 §2.4 was the wrong index, not a missing function.

So **"installed" must mean the index GAUSS resolves**, by `gauss.cfg`'s order, not any file with a matching name.

### 2.2 Three index formats

| Format | Example | Lists symbols? | What `library` defines |
|---|---|---|---|
| legacy, absolute source paths | `pkgs\tsmt\lib\tsmt.lcg` | yes (`name : proc : line`) | the listed symbols |
| generated, relative source paths | `pkgs\timeseries\lib\tsmt.lcg`, `gml.lcg` | yes | the listed symbols |
| source paths only | `pkgs\timeseries\lib\timeseries.lcg` | **no** | **nothing**: after `library timeseries;`, `garchFit` is `G0025` and `struct garchResult` is `G0507` (lb05, lb10) |

Entry kinds across every installed index: `proc` 3,725, `matrix` 304, `definition` (structures) 270, `string` 32, `keyword` 8.

This machine's `timeseries` code is incomplete: after `library tsmt;`, `garchFit` stops with "garchFit: Not yet implemented. Rust backend required." (lb11), and `arimaFit` fails to load `c:\gauss26\dlib\gausslib_ts.dll` (`G0432`, lb13). GML works (82.13; lb08). So presence in the index means "GAUSS will find it", not "it works". The handoff already reports runtime failure honestly (v0.89 §11; "values are never evaluated").

### 2.6 Package internals touch the system

`check_system_statements(...)` over every installed package's `src\*.src`: nearly every package has findings. They are internal plumbing (`errorlog`/`errorlogat` messages; `#include` of the package's own `.sdf`/`.dec`), Aptech's native code (`dllcall`/`dlibrary`: GML 21, `timeseries` 131), and, in `tsmt`, dataset-file handling (`loadd`, `open`, `readr` on a file name the caller passes). A rule that a package's source must be free of system statements would exclude every package, GML included.

### 2.7 Docs and packages

Package pages live in folders (`tsmt/` 92, `timeseries/` 84, `tspdlib/` 67, `cmlmt/` 31, `sslib/` 26, `mlmt/` 25, `comt/` 22, `optmt/` 20, …), but GML's are top-level (`lassofit.rst`). So the docs alone cannot say which package defines a symbol; the resolved index can.

## 3. Proposed design

### 3.1 Resolve the installation (new, read-only)

A new module `gauss_installed_libraries.py` (stdlib only), given the configured `gauss_executable`:
- `GAUSSDIR` is the executable's directory; read that directory's `gauss.cfg` only. Expand `$(GAUSSDIR)` and `$(PACKAGEDIR)` and each `*` (sorted, case-insensitively), in the order lb01 shows: `extra_lib_path`, then `lib_path`. Any other variable, or a missing or unreadable `gauss.cfg`, means **no installation evidence** (§3.4).
- `resolve(name)`: the first `<name>.lcg` in that order, case-insensitive.
- `symbols(index)`: the `name : kind : line` entries. A paths-only index defines nothing (lb05). `gauss.lcg` and `user.lcg` are read too, so the validator knows what is always loaded.
- Deterministic, no GAUSS launch, no network. The result carries each index's path and SHA-256 (§3.5).

### 3.2 Which packages count

A curated `_INSTALLED_LIBRARY_REGISTRY` lists Aptech-documented packages by name, each with its docs evidence (a docs folder, or for GML its top-level pages). Proposed members: `gml`, `tsmt` (the alias), `tspdlib`, `cmlmt`, `comt`, `maxlikmt`, `optmt`, `coint`, `sslib`. A name that is not registered, a registered name that does not resolve, or `timeseries` (paths only, defines nothing) stays `not_ready`, with a reason that says which.

### 3.3 The validator

- **A `library` statement** that is a bare, top-level `library a[, b …];` naming only registered, resolved packages is no longer `source_inclusion`. Anything else stays `not_ready`: a quoted or path argument, `library` inside a procedure or a control-flow block, an unknown or unresolved name (lb14 continues after `G0290`, so a missing library must block). Only the **last** `library` statement counts (lb16), wherever it is (lb15).
- **Each called symbol** that is not user-defined and not in `gauss.lcg` or the core docs must be listed in an active library's index. If it is listed only in an installed but inactive package, the call is `not_ready`, naming the library it needs (GAUSS: `G0025`). **This fixes the reverse gap (§1)**, wherever an installation is known.
- **Package calls are checked like any other call:** the docs page's signature, roles, preconditions and syntax. A function with no extracted signature stays `review_required`, as today.
- **User-supplied file arguments stay blocked.** The v0.89.3 dataset-argument rule extends to registered package functions whose documented parameter takes a file or dataset name (curated, citing each page's `:param` text; for example `trainTestSplit`'s file-name form). Package functions whose documented purpose is writing a file are added to the system-statement registry.
- **Package internals are trusted** like built-in functions, which also call native code internally. §2.6 is disclosed, not checked.

### 3.4 Without installation evidence

No configured executable, the fake runner, or an unreadable `gauss.cfg`: `library` stays `not_ready` as today. A call to a symbol documented on a package page becomes `review_required` ("package membership cannot be confirmed without the configured GAUSS installation"), instead of `handoff_candidate`. Without a real executable nothing can run anyway; this only stops the verdict from overstating.

### 3.5 Binding

The validation result records each active library's resolved path and SHA-256. `gauss_execution_prepare` re-resolves them and refuses with the existing `validation_stale` if any changed, like v0.87.0's docs check. The handoff prompt lists the active libraries ("Libraries: gml (C:\gauss26\pkgs\gml\lib\gml.lcg)").

### 3.6 Reporting

`gauss_session_start` and `gauss-ai doctor` report the registered packages that resolve, and the ones installed but not registered, so a client never needs the shell (82.12).

## 4. Scope boundary

In scope: §3, its tests, the §6 diffs, `docs/pre-execution-validation.md`, `docs/mcp-server.md` (what can never be executed), `KNOWN_LIMITATIONS.md`, the release records and live evaluation 83.x.

Out of scope: `#include`, `run`, `dlibrary`/`dllcall` in user code, `library` with a path, installing or updating packages, non-Aptech packages, checking package source, `timeseries`'s missing native backend (§2.5), named default arguments (v0.90 class C).

## 5. Safety

- **What is relaxed:** one statement shape, `library` with registered names, so that Aptech package code (which may call Aptech native libraries internally) runs inside an approved handoff. This is what the user signed off on 2026-10-29.
- **What is not relaxed:** every other system statement in the user's code; file and dataset arguments the user passes (§3.3); the digest-bound, single-use, human-approved handoff; the deleted temporary working directory.
- **Residual risk, disclosed:** a package procedure could write a file with a path built internally, or read an environment-dependent location. The run directory is deleted afterwards, and the prompt names the libraries. The curated registry (§3.2) keeps the trust to Aptech's own packages.

### 8.1 How decision 1(b) is applied

Matching a package's procedure names to docs page names (§2.4) is not enough: `dccelib`'s `cdtest`, `cips` and `plotResiduals` match pages of *other* packages (`tsmt/cdtest.rst`, `tspdlib/docs/cips.rst`, `timeseries/plotresiduals.rst`), and `coint`'s `lagn` matches a core page. Under a literal reading those calls would be checked against another function's signature. So a page counts for a library only when it is **attributed** to it:
- the page's own examples load that library (`library gml;` on 24 top-level GML pages), or
- the page sits in a docs folder whose pages' examples load that library (`mlmt/` → `maxlikmt`, `timeseries/` → `timeseries`, `tsmt/` → `tsmt`, …), the folder's library being the one its pages load most often.

A `library <name>;` statement is allowed when `<name>` resolves (§3.1) and its index defines at least one symbol whose page is attributed to `<name>` or to the package directory holding the index (so `tsmt`, resolved to `pkgs\timeseries\lib\tsmt.lcg`, counts through the `timeseries/` pages). On this machine that admits `cmlmt`, `comt`, `gml`, `maxlikmt`, `optmt`, `sslib`, `tsmt`, `tspdlib` and `pgraph`, and not `coint`, `dccelib`, `pubtable`, `qardl`, `quaids` or `timeseries` (paths only). The curated registry of §3.2 is dropped.

A symbol needs a library (decision 2) only when every docs page with its name is attributed to a package; a symbol with a core page (`lagn.rst`) never does.

### 8.2 Found while applying it

- **The docs' `timeseries/` examples (61 pages) say `library timeseries;`**, which defines nothing on this installation (lb05); the functions are reachable only through `library tsmt;`. Code written from those pages is `not_ready` here with a reason naming `tsmt`, which is what GAUSS 26.1.4 does (`G0025`). GAUSS 27 on this machine has only `optmt`, so the paths-only index cannot be compared across versions.

### 13.1 Change

- **A declared structure type must be loaded.** `analyze_libraries(...)` reads each `struct T name;` declaration (not a definition `struct T {`, and not a `proc (struct T)` header). If the code does not define `T` and no active or always-loaded index lists it, but **some** index on the search path does, the declaration is `library_required` with GAUSS's reason (`G0507`): "defined by the installed library `L` ... (add `library L;`)" when `L` is usable here, otherwise "defined only by <index path>". `Installation.all_indexes()` (new) lists every `.lcg` on the search path, **shadowed ones included**, because the shadowed legacy `pkgs\tsmt\lib\tsmt.lcg` is the only index defining `garchEstimation` (83.7). A type no index lists is left as before: the core structures (`DS`, `PV`, `olsmtControl`, …) are in the always-loaded `gauss.lcg`.
- **Wording (83.11):** the `pgraph` refusal now says it "is installed with GAUSS itself (…) but is not a package".
