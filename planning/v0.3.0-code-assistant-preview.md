# v0.3.0 Code Assistant Preview Plan

## Release Goal

Make the GAUSS Code Assistant usable and understandable by someone who was not part of the design conversation.

## Scope

- Improve Code Assistant user-facing documentation.
- Provide a manual quickstart.
- Add practical examples for common tasks.
- Clarify limitations and safe-use expectations.
- Strengthen retrieval guidance for official command documentation.
- Broaden benchmark coverage where high-value gaps remain.

## Non-Goals

- Full automation.
- GAUSS runtime execution.
- Complete indexing of every GAUSS command page.
- Public launch.
- Replacement of official GAUSS documentation.

## Required Deliverables

- [Code Assistant README](../agents/code-assistant/README.md)
- [Code Assistant quickstart](../agents/code-assistant/QUICKSTART.md)
- [Code Assistant examples](../examples/code-assistant/README.md)
- Updated roadmap and changelog.
- Current [benchmark coverage tracker](../evaluations/benchmark-coverage.md).
- Clear [known limitations](../KNOWN_LIMITATIONS.md) and safe-use guidance.

## Suggested Manual Evaluations Before Tagging

- Prompt 1.1: Matrix summary procedure.
- Prompt 1.3: DataFrame cleaning script.
- Prompt 6.2: Control structure defaults.
- Prompt 7.2: String processing efficiency.
- Prompt 10.2: Beginner vs advanced response.

## v0.3.0 Readiness Checklist

- Code Assistant README is complete.
- Quickstart is complete.
- Examples are complete.
- Known limitations are linked.
- Evaluation coverage is updated.
- At least one manual evaluation exists for major task categories.
- Public-facing README language is clear.
- No private paths or sensitive internal references are present.
- No unverified GAUSS syntax examples are presented as production-ready.
- A new user can identify which files define the Code Assistant.
- A new user can run a manual prompt using the quickstart.
- Retrieval guidance clearly says official command docs are authoritative.
- Benchmark coverage identifies what has and has not been evaluated.

## Risks

- Users may treat benchmark responses as official documentation.
- Users may over-trust command category membership as exact syntax evidence.
- The assistant may still produce plausible but invalid GAUSS syntax without retrieval.
- Manual evaluation may not catch regressions across all task modes.
- Quickstart examples may become stale as workflows evolve.

## Open Questions

- Which official documentation source should be used first for command-specific retrieval in a preview setup?
- Should preview users get a minimal context bundle for manual testing?
- Which commands deserve short curated notes beyond `olsmt`?
- What threshold of benchmark coverage is enough for a `v0.3.0` private preview?
