## 2. v0.76.0 gap analysis (Phase 1, completed before any validator edit)

- **Why the bare multi-token literal false negative mattered:** it was found by an *incidental* CLI subprocess smoke test, performed *after* `v0.76.0`'s own planned 12-scenario live evaluation had already concluded and been reported as complete. The validator had already shipped one gap (semicolon row separators); a second, structurally different gap (`x = -1 0;`, no braces at all) existed in the same shipped version and was only found by chance. This is direct evidence that a fixed-size scenario list cannot bound false-negative risk — it can only report what it happened to try.
- **Why the planned 10-scenario evaluation was insufficient:** of 10 code-bearing `66.x` scenarios, only 1 reached `HANDOFF_CANDIDATE`; the rest were `REVIEW_REQUIRED`/`NOT_READY`/produced no code at all. A sample this small, dominated by REVIEW_REQUIRED outcomes, cannot distinguish "the validator is solid" from "the validator has not yet been shown a shape it gets wrong." The post-release evidence review (recorded in `PROJECT_STATUS.md` before this milestone began) concluded explicitly that execution handoff was not yet justified specifically because checker completeness was unmeasured.
- **Why corpus differential testing was chosen** over more live scenarios: a live scenario tests what the model happens to write, once, for one prompt. A corpus — documentation-derived valid syntax, systematic mutations, and historical/fresh real model output — tests a bounded but *broad and reproducible* set of shapes, every one scored against a real GAUSS oracle, with every disagreement preserved as evidence. It converts "we haven't seen a counterexample yet" into "we measured N snippets and found exactly these M disagreements."

## 3. Differential harness

- **Architecture**: `scripts/gauss_differential_harness.py` (runner, classifier, reporting) + `scripts/gauss_syntax_mutations.py` (17 mutation operators) + `scripts/build_differential_corpus.py` (corpus builder). See `docs/differential-syntax-validation.md` for the full architecture description, oracle classification table, and agreement-class definitions — not duplicated here.
- **Real-GAUSS outcome classification**: `ACCEPTED` / `REJECTED_SYNTAX_OR_PARSE` / `RUNTIME_ERROR` / `TIMEOUT` / `INFRASTRUCTURE_FAILURE`, driven by `gauss_error_catalog.py`'s `GaussErrorCategory.PARSE_SYNTAX` vs. non-syntax categories. Fail-closed: an uncatalogued error code is recorded but never used to assert agreement/disagreement.
- **Agreement classes**: `AGREE_ACCEPT` / `AGREE_REJECT` / `FALSE_POSITIVE` / `FALSE_NEGATIVE` / `INCONCLUSIVE`. `PARTIAL`/`UNKNOWN` validator statuses are never flattened into `VALIDATED`/`INVALID`.
- **Outputs/artifacts**: `evaluations/differential_corpus/*.jsonl` (committed corpus, static, reproducible without a live docs_root/GAUSS install) and `evaluations/differential_runs/<date>-<label>/{results.jsonl,summary.md,summary.json}` (committed baseline + post-fix results, never overwritten).
- **Reuse of existing runner**: real GAUSS invocation goes through `gauss_execution_adapter.GaussExecutionAdapter` + `load_real_helper()` → `gauss_code_execution.execute_gauss_code` — the exact production path `test_gauss_execution_adapter_real.py` already established. No new subprocess-management code was written. Real invocation is gated by the same `--run-real-gauss` + `GAUSS_AI_ALLOW_REAL_EXECUTION=1` double-gate that file already uses.

## 5. Baseline results (before any validator fix)

`evaluations/differential_runs/2026-09-18-baseline/summary.md` (214 items — the corpus before `model_output_fresh` existed):

- Agreement classes: `inconclusive` 104, `agree_accept` 77, `agree_reject` 16, **`false_positive` 12**, **`false_negative` 5**.
- **False negatives (5, all `mutation`):** `B-057` (`meanc(rndu(1e5 4))`), `B-058` (`rndn(n n)`), `B-059` (`reshape(5 3)`), `B-061` (`sprintf("..." pi)`), `B-063` (`ones(3 2)`) — all one shape: two call-argument tokens separated only by whitespace, no comma. All independently confirmed real `error G0063` via `tgauss.exe -b`.
- **False positives (12):** 4 from `matrix_literal_row_separator` firing on a confirmed-silent-misparse (correct, intentional strictness, not a defect — see §6); 7 from the now-removed `call_argument_separator` rule firing on a doubled/trailing comma GAUSS genuinely tolerates; 1 (`B-025`) from `balanced_delimiters` firing on a stray, unopened `}` inside a `let` statement that GAUSS also does not hard-error on.
- Major failure clusters: (1) missing-separator-in-call-argument (5 false negatives, one root cause), (2) tolerated-stray-comma (7 false positives, one root cause), (3) semicolon-matrix-literal intentional divergence (4 false positives, by design), (4) one open `let`-statement edge case.

## 6. Validator hardening

| Cluster | Root cause | Fix | Regression | General or one-off |
|---|---|---|---|---|
| 5 false negatives (missing call-argument separator) | No rule existed for two adjacent bare tokens inside one call argument. | New rule `call_argument_missing_separator` (masks matrix-literal/indexing spans first, so a legitimate literal/index list is never mistaken for the violation). | `test_108`–`test_114`, `test_gauss_pre_execution_validation.py`. | **General** — one rule, applies to any call, not per-symbol. |
| 7 false positives (tolerated stray/trailing comma) | `call_argument_separator` was never backed by real evidence, only a structural assumption. | Rule **removed entirely** — real `tgauss.exe -b` (`ones(3,, 2)`/`meanc(rndu(1e5,, 4))`, verified with `print`) showed the doubled comma is silently and *correctly* collapsed, not a misparse. | `test_86c`/`test_86d` rewritten to assert the opposite, with an inline comment explaining why the old expectation was superseded. | **General** — a full rule removal, not a narrowed exception. |
| 1 new false negative found by the live stress batch (`D-007`, `print("..." std_dev)`) | `call_argument_missing_separator` skipped the wider `_LANGUAGE_CONSTRUCT_KEYWORDS` set, which includes `print` (to avoid misreading GAUSS's bare `print x, y;` form) — silently exempting every parenthesized `print(...)` call. | Narrowed the skip list to `_BLOCK_CONSTRUCT_KEYWORDS` (genuine loop/conditional/proc headers only). | `test_115`–`test_117`. | **General** — fixes every simple-statement keyword used in parenthesized-call form, not just `print`. |
| 4→6 false positives (semicolon matrix literal) | Real GAUSS's process exits cleanly on a `;`-separated literal — it silently misparses it. | **No fix** — kept intentionally `INVALID`. Re-confirmed live this milestone (`+DEN` denormal token observed in real output). | Pre-existing `test_*` coverage; documented as an intentional divergence in `docs/differential-syntax-validation.md`. | Documented exception, not a rule change. |
| 1 false positive (`B-062`, `sprintf("..." x)` with `x` undefined) | Real GAUSS's own undefined-symbol check can mask the underlying `G0063` syntax error, confirmed by A/B testing (`x = 5;` prefix flips `G0025`→`G0063` for the byte-identical malformed statement). | **No fix** — this is a genuine real-GAUSS-oracle limitation, not a validator defect (the rule is proven correct by the defined-`x` case). | Documented in `docs/differential-syntax-validation.md`. | Documented oracle limitation. |
| 1 false positive (`B-025`, stray unopened `}` in a `let` statement) | `balanced_delimiters` flags a genuinely unmatched delimiter; GAUSS's `let` parser tolerates it without erroring, but produces empty/ambiguous output (not a clean, obviously-correct result either). | **No fix** — open, disclosed limitation. | Documented in `docs/differential-syntax-validation.md`. | Documented, unresolved limitation. |

Also cataloged `G0063` in `gauss_error_catalog.py` (`PARSE_SYNTAX`, `REAL_RUNTIME`) — required for the harness's own oracle classification to recognize it.

## 7. Parser decision

**Retained the bounded, rule-based validator.** After hardening, it holds seven deterministic rules (was six at `v0.76.0`: one removed, two added net +1), each independently justified by real documentation text or real `tgauss.exe` evidence. The one rule change that removed a check did so because real evidence contradicted its justification — itself evidence the current discipline (require real evidence, not intuition, for every rule) works, rather than accumulating special-case cruft. A bounded parser remains a live option for a future milestone if rule count/interaction complexity grows further; this milestone's own evidence (small, targeted fixes, each closing a real cluster) does not yet justify that jump.

## 10. Grounding-token-cap issue

- **Fix**: `gauss_conversation_engine._candidate_tokens(...)` now collects every candidate token, ranks by a 4-tier priority (call-shaped in the question > curated concept-alias symbol > recently confirmed topic > cached exact documented-symbol filename stem, via a one-time-per-`docs_root`, `functools.lru_cache`d filename-only scan), then truncates to `MAX_TOKEN_LOOKUPS`.
- **Effect on the original regression wording**: closed. `_candidate_tokens("Write GAUSS code that computes the column means of a reshaped 2x3 version of a 6-element vector x, using meanc and reshape.", docs_root=...)` now returns `['meanc', 'reshape', 'computes', 'means', 'reshaped', 'version']` (both target functions present) where it previously returned neither. Confirmed live end to end (`67.9`).
- **Lookup bound**: unchanged. `MAX_TOKEN_LOOKUPS = 6` still bounds the number of real `command_doc_lookup.lookup(...)` calls per question; the fix only reorders which 6 candidates are chosen, adding no new retrieval calls (the one-time cached filename scan is not a per-question retrieval call).

## 17. Remaining limitations

- **Unsupported grammar**: still no `do`/`while`/`for`/`if`/`proc` block-body checking, string concatenation (`$+`), complex/scientific-notation literal validation beyond structural checks, or character-element matrix-literal deep validation — recorded honestly as `PARTIAL`/`unknown_constructs`, never guessed.
- **PARTIAL/UNKNOWN syntax**: still never collapsed into `VALIDATED`/`INVALID` for readiness purposes; `REVIEW_REQUIRED` remains the conservative default.
- **Runtime-only semantics**: real GAUSS is an oracle for syntax acceptance only, never for methodological/statistical correctness — a `RUNTIME_ERROR` outcome says nothing about whether a computation is appropriate.
- **Unverified preconditions**: unchanged from `v0.76.0` — a runtime-variable argument to a documented-precondition function is always `UNVERIFIED`, never guessed.
- **Incomplete docs/signature coverage**: `67.6` found `sprintf`'s documented-signature extraction only captured a 2-argument overload, incorrectly flagging a real 3-argument call `INELIGIBLE` — a pre-existing (`v0.74.0`-era) signature-extraction limitation, disclosed, not fixed (out of this milestone's scope).
- **Model dependence**: the semicolon-matrix-literal shape and the missing-call-argument-separator shape were both observed live, unprompted, multiple times across independent prompts — real, repeatable model behaviors, not synthetic constructions.
- **docs-root dependency**: the grounding-cap fix's tier-3 priority (exact documented-symbol filename match) requires a configured `docs_root`; without one, only tiers 0–2 apply (still strictly better than the pre-fix behavior, never worse).
- **Real GAUSS oracle limitations**: `B-062` (§6) is a genuine, disclosed limitation of using GAUSS's own error *code* as ground truth — the same syntax defect can surface as either a syntax- or runtime-category code depending on incidental, syntax-irrelevant program state.
- **No conversational execution**: unchanged — this milestone added no execution capability of any kind (§14).
- **Anthropic live-test status**: unchanged from prior milestones — no live Anthropic API round trip was performed (no API key available in this environment); this milestone's live work used only the real local Ollama provider.

## 18. Recommendation

**Continued alpha testing is supported; controlled execution handoff as `v0.78` is a reasonable next decision for the user to make, but is not being started automatically.**

Evidence supporting readiness to *consider* it: zero remaining false negatives across a 239-item systematic corpus (up from 5 at baseline); the one HANDOFF_CANDIDATE-class scenario in the tested corpus is real-GAUSS-confirmed accepted; the runtime-variable precondition path is now exercised live, not only by unit test; the grounding-candidate-cap limitation is fixed. Evidence urging caution: `HANDOFF_CANDIDATE` remains rare in idiomatic model output (the same parameter-role/variable-indirection limitation `v0.76.0` disclosed is unchanged — this milestone did not attempt to fix it, per its own scope); the real-GAUSS-oracle limitation found this milestone (`B-062`) shows that even a well-evidenced validator rule can have its correctness partially obscured by GAUSS's own error-reporting behavior in edge cases; and a bounded 239-item corpus, however systematic, is still not exhaustive — a fourth false negative could exist in a shape not yet sampled. Per `CLAUDE.md`'s workflow rule and this milestone's own instructions: **`v0.78` is not started by this session.** The decision is the user's, informed by this report.
