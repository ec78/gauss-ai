# v0.6.0 Readiness Checklist

This checklist audits whether the repository is close to tagging `v0.6.0` - Tool Interface and Evidence Schema. It is an audit record only; it does not tag a release.

## Release Goal

`v0.6.0` proves that GAUSS AI can represent command lookup evidence in a structured, versioned schema; validate that evidence mechanically; generate schema-aligned lookup output from the existing retrieval prototype without breaking backward compatibility; and evaluate Code Assistant behavior across the full range of realistic evidence states (valid, incomplete, not found, ambiguous, conflicting, stale, and structurally invalid).

All seven Evidence Schema benchmarks pass with no automatic failure conditions triggered in any run, and every run demonstrates the same underlying discipline: inspect the actual evidence/tool output rather than trust an assumed premise, whether that premise came from the user's question or the benchmark's own wording.

## Remaining Limitations

- Schema validation checks structure (required fields, enum values, types), not GAUSS correctness — a schema-valid object can still describe incorrect or outdated command behavior.
- The evidence schema does not replace official GAUSS documentation, which remains authoritative for exact syntax, defaults, and return values.
- Lookup evidence can become stale relative to official docs; the schema can represent staleness (`stale_evidence`) but cannot yet detect it automatically.
- Several evidence states (ambiguous, conflict, stale, schema-invalid) currently require hand-built synthetic fixtures, since `scripts/command_doc_lookup.py` does not yet generate them from real lookups.
- Conflict and stale evidence are represented in the schema but not yet generated automatically by `command_doc_lookup.py` — there is no curated-note comparison logic or staleness-detection logic in the script yet.
- The validator's path-detection heuristic can produce false positives for official documentation examples that happen to contain path-shaped strings (confirmed directly: the real `olsmt.evidence.json` triggers two such warnings from a legitimate HDF5-URI doc example).
- The system still does not execute GAUSS code; nothing in the evidence schema or validator runs or checks GAUSS syntax at runtime.

## Blockers

- **`KNOWN_LIMITATIONS.md` is stale.** It targets the `v0.5.0` milestone by name and does not mention the evidence schema, validator, `--schema-output`, or any schema-specific limitation at all. This is a required deliverable per this checklist and currently omits an entire milestone's worth of new capability and limitation. Recommended fix: update the intro line to the current milestone and add the schema-specific limitations already listed above (structure-only validation, fixture-dependent states, path-warning false positives, no automatic conflict/staleness detection).

No other blockers were found:
- All other required files exist and are current.
- All seven Evidence Schema evaluations passed; none failed or are missing.
- All fixtures and both schema-aligned examples were re-validated during this audit and behave as documented (5 fixtures + 2 real examples pass; the one intentionally-invalid fixture correctly fails).
- `CHANGELOG.md` and `ROADMAP.md` both reflect the evidence schema work delivered.
- Legacy lookup JSON files (`olsmt.lookup.json`, `strindx.lookup.json`) were confirmed untouched (last modified 2026-07-02, before this milestone's work began).
- No release tag was created by this or any prior `v0.6.0` audit task.

## Non-blocking Follow-ups

- Add schema-aligned output tests (beyond manual `--json`/`--strict` spot checks already performed).
- Add an automated validator CI step once the repository has CI infrastructure.
- Improve stale-evidence detection (currently representable but not automatically detected).
- Add conflict-generation or curated-note comparison logic to `scripts/command_doc_lookup.py` so `conflict`/`stale` states can arise from real lookups, not only fixtures.
- Improve handling of validator path-warning false positives (for example, skip matches inside recognized non-local URI schemes or literal code-block text).
- Add more real command examples beyond `olsmt` and `strindx` to widen schema-aligned pilot coverage.
- Add a schema versioning policy for `schema_version` beyond the current fixed `"0.1.0"`.
- Consider making `command_doc_lookup.py` emit `conflict`/`stale` states automatically when appropriate data is available.

## Readiness Recommendation

**Ready with non-blocking follow-ups, pending the `KNOWN_LIMITATIONS.md` update.**

Rationale: every required deliverable exists and is current except `KNOWN_LIMITATIONS.md`, which is a small, well-scoped documentation fix (update the milestone reference and add the schema-specific limitations already identified above), not a functional gap. All seven Evidence Schema benchmarks pass with real, re-verified evidence — including the intentionally-invalid fixture correctly failing and the two real schema-aligned examples correctly passing with their expected warning profiles. The non-blocking follow-ups above are reasonable to defer to `v0.7.0` or later without weakening this milestone's "structured but still prototype-stage" framing.

## Suggested Release Notes

```text
v0.6.0 - Tool Interface and Evidence Schema

- Added a formal JSON Schema (schemas/command_lookup_evidence.schema.json)
  for command lookup evidence: retrieval status, source authority,
  confidence, matches, ambiguity, conflicts, and staleness.
- Added a lightweight validator (scripts/validate_lookup_evidence.py)
  with pass/fail/warning reporting, --strict and --json modes, and a
  clear dependency error when jsonschema is not installed.
- Added --schema-output to scripts/command_doc_lookup.py, producing
  schema-aligned evidence while preserving the existing default output
  format unchanged.
- Added five schema fixtures (valid, invalid, ambiguous, conflict,
  stale) and two real schema-aligned examples (olsmt, strindx).
- Added and evaluated Evidence Schema benchmark prompts 13.1-13.7,
  all passing: valid evidence, stale evidence, official-vs-curated
  conflicts, ambiguity, incomplete extraction, schema validation
  failure, and validator warning handling.

This remains a local-first prototype. Schema validation checks
structure, not GAUSS correctness. Official GAUSS documentation
remains authoritative.
```
