# v0.81.0 — Idiomatic Client-Written Code Reaches HANDOFF_CANDIDATE: Design

## 1. Why

The v0.79/v0.80 hybrid path exists so that a client model (Claude, ChatGPT) writes the GAUSS code and gauss-ai computes the verdict. But code written the way models naturally write it almost never reached `handoff_candidate`. Live evaluations 66.1, 66.2, 66.10 and 70.6 reached candidacy only when the prompt coaxed a call with a literal argument (`y = meanc({1 2, 3 4});`).

The readiness policy itself is unchanged. Every snippet below reaches candidacy through **more real evidence**: `compute_handoff_readiness`, `compute_evidence_profile`, the BROAD requirement, `compute_eligibility` and `_SYSTEM_STATEMENT_REGISTRY` have zero diff.

## 2. Gaps found during planning

Probing `validate_code` against the real docs checkout showed that `PROJECT_STATUS.md`'s diagnosis ("`rndu`'s signature can't be extracted") was wrong for the MCP path. There, `rndu`, `rndn`, `rows`, `cols`, `zeros`, `ones`, `seqa`, `eye`, `reshape` and `invpd` all extract fine. The real causes:

| Snippet | v0.80.0 | Cause |
|---|---|---|
| `x = {1 2, 3 4}; y = meanc(x);` | review_required | role check never traced a variable → `parameter_role_check` UNKNOWN → evidence not BROAD |
| `x = rndu(100, 4); y = meanc(x);` | review_required | same: `x` comes from a call |
| `x = rndu(1e5, 4); …` | review_required | `1e5` did not match `_NUMERIC_LITERAL_RE` |
| `n = 5; x = zeros(n, 1);` | review_required | scalar variable untraced |
| `y = meanc({1,2,3});` | **not_ready** | **false MISMATCH**: vector literal vs documented `matrix` |
| `y = meanc(5);` | **not_ready** | **false MISMATCH**: scalar vs documented `matrix` |
| `x={2 1,1 2}; y=invpd(x); x={-1 0,0 -1};` | **not_ready** | **false VIOLATED**: precondition tracer used the last assignment anywhere, even one after the call |

- The "`rndu` signature unknown" seen in run `2026-09-12-…-run-002` is real, but only on the **`ask()` path**. There, `validate_generated_code` extracted signatures only for the turn's grounded topics, so a called builtin such as `rndu` got none.
- **Ordering hazard:** tracing variables without first fixing the false MISMATCH would have pushed `x = {1,2,3}; m = meanc(x);` from review_required to not_ready. The compatibility fix (§3.1) therefore lands first.

## 3. Changes

All changes are deterministic and in `scripts/gauss_pre_execution_validation.py` unless noted.

### 3.1 GAUSS category compatibility (`_CATEGORY_ACCEPTS`)
In GAUSS everything numeric is a matrix. The docs say so themselves:
- `stof.rst`: "*x* will be a 1x1 matrix equal to 3.14";
- `between.rst`: `:type left: 1x1 matrix`;
- `meanc.rst` documents its own column-vector result as `:rtype y: Kx1 matrix`.

The new compatibility rules:
- A documented `matrix` accepts matrix, vector and scalar.
- A documented `vector` accepts vector and scalar.
- `scalar`, `string`, `control` and `dataset` accept only themselves.

So `meanc("abc")` and `zeros({1 2}, 3)` remain MISMATCH → not_ready.

### 3.2 Exponent-form numerals
`_NUMERIC_LITERAL_RE` now accepts `1e5`, `1.5E-3`, `.5` and `3.`. The real `meanc.rst` example is `meanc(rndu(1e5, 4))`, and models copy it.

### 3.3 One shared assignment resolver
`_governing_assignment(name, code, line_number, column)` answers "which assignment gives `name` its value at this call?". It returns the right-hand side of the most recent plain top-level `name = …;` statement that ends before the call. `GeneratedCall.column` (new, defaulted) orders same-line statements.

It refuses (`None`, an honest gap) if `name` is also written in any way it does not model:
- inside an `if`/`for`/`do`/`proc` block;
- as an indexed or member target (`x[1,1] = 5`);
- as one of several targets (`{x, y} = f()`);
- as a `for` loop variable;
- by `clear`.

String contents are masked.

It has two users:
- **Role check:** `resolve_argument_category(...)` resolves an argument as a literal, then as a traced literal (`TRACED_LITERAL`), then as a single call `f(...)` whose own docs give a classifiable first `:rtype` (`DOCUMENTED_RETURN`; `DocumentedSignature.return_categories`, new). A `DOCUMENTED_RETURN` disagreement is UNKNOWN, never MISMATCH, because a documented "matrix" may be 1×1 at run time. `ParameterRoleCheck.origin` (new, defaulted) records which path was used, and the explanation names the trace.
- **Precondition tracer:** `_find_literal_matrix_for_argument` now uses the same resolver. This fixes the post-call-reassignment false VIOLATED. It also fixes a literal-followed-by-operator misread: `x = {2 1, 1 2} * -1` was read as the bare literal and is now UNVERIFIED.

### 3.4 Signatures for called-but-not-grounded documented symbols
In `gauss_conversation_engine.validate_generated_code`, each called symbol that is documented (a `_COMMON_BUILTIN_SYMBOLS` entry or an earlier turn's topic) but has no signature now gets one bounded `lookup(...)`:
- capped at `MAX_VALIDATE_CODE_SYMBOLS`;
- requires confidence ≥ `MIN_DOC_CONFIDENCE`.

This is checking evidence only: the grounding bundle and generation gate are already computed and unaffected. Role checks now run per block, with that block's code and all known signatures.

### 3.5 Ambiguous lookups resolved by a page's own call definition (added after the re-baseline)
`_resolve_ambiguous_by_definition(symbol, result)` lives in `gauss_conversation_engine` and is applied to both `resolve_concepts` and `validate_code`. It turns an `"ambiguous"` lookup into `"found"` only when **exactly one** candidate page meets both conditions:
- its own syntax blocks define `symbol(...)` as a whole-name call;
- its confidence is at least `MIN_DOC_CONFIDENCE`.

Zero or several defining pages leave the lookup ambiguous. `command_doc_lookup` itself is unchanged.

## 4. Deviations from the approved plan

- **Resolver rule.** The plan said "exactly one assignment in the snippet". Implementing it showed that rule would *weaken* a real protection: `x = {2 1,1 2}; x = {-1 0,0 -1}; y = invpd(x);` is correctly VIOLATED, and "exactly one" would have dropped it to UNVERIFIED. The resolver therefore uses the *most recent prior top-level* assignment and refuses on any write it doesn't model (§3.3). That case is tested to stay not_ready.

- **Added scope (user-approved 2026-10-08): §3.5.**
  - **Re-baseline result.** `gauss-ai docs fetch` downloaded 1,826 pages on 2026-10-08. 18 snippets and 18 builtins gave **identical** verdicts, signatures and return types against the old clone and the published copy.
  - **The defect it surfaced.** The wider snippet set found a pre-existing false `not_ready`: `x = rndu(5, 2); v = vcx(x);`, where `vcmvcx.rst` and `vcmsvcxs.rst` scored within the ambiguity margin. v0.80.0 behaved the same.

Five plain-language tasks were asked through a real connected Claude Code client. The client wrote the code with no steering (`evaluations/runs/2026-10-08-code-assistant-idiomatic-handoff-candidacy-run-001`-`005`).

| ID | Task | Verdict | Score |
|---|---|---|---|
| 71.1 | random data, column means (`rndn` -> `meanc`) | handoff_candidate; real-GAUSS prepare refused by the operator gate | 4.0 |
| 71.2 | OLS by hand (`invpd(x'x)*x'y`) | review_required, by design (§6) | 4.0 |
| 71.3 | zeros, then fill in a `for` loop | review_required: the `for` block caps syntax coverage at partial | 3.0 |

- **The goal is met for straight-line code.** Every straight-line, literal-or-call-fed snippet reached candidacy.
- **The remaining gap is control flow.** It was not named in this doc before the live run: the syntax layer, not the tracer, is what blocks 71.3.
- **Not run live:** the planned negative probes (hallucinated symbol, SPD violation through a variable, system statement). They were last run live in 70.2-70.4 on v0.80.0, and `test_gauss_conversation_engine.py` 123-126 covers them through traced variables.

## 6. Known limitations

- Expressions are never evaluated. `invpd(x'x)`, `x*2` and `x + 1` stay UNKNOWN, so the documented OLS idiom `b = invpd(x'x)*x'y` remains review_required by design.
- Tracing is one level only: `y = x; f(y)` is not followed through `x`.
- Any write inside a control-flow block makes that variable untraceable for the whole snippet, even when the write cannot reach the call.
- `DOCUMENTED_RETURN` uses only the first `:rtype` and only for a right-hand side that is exactly one call.
- The signature re-lookup in `validate_generated_code` still takes the top-scoring page. If a disambiguated defining page were not the top scorer, its signature would come back unknown and the result would be `review_required` (the safe direction). For `vcx` it is the top scorer.
- Pass-by-pointer writes (`&x`) are not modelled. GAUSS procs receive arguments by value; struct pointers are already outside what the role check classifies.
- Any control-flow block caps syntax coverage at partial, so preallocate-and-fill loops stay review_required (found live, 71.3).
