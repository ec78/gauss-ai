# v0.73.0 — Grounding-Gated Generation & GAUSS Function Resolution

## 1. Objective

Move grounding from disclosure-only to active generation control, and add deterministic natural-language-to-symbol resolution, so unsupported GAUSS syntax is structurally harder to produce regardless of the underlying model's own reliability. Directly motivated by `v0.72.0`'s own live-evaluation failures (a `colmean` hallucination in place of the real `meanc`; a fabricated panel-regression syntax pattern).

## 2. v0.72.0 failure analysis

**`colmean` root cause**: primarily a **retrieval/resolution** problem, not a prompting or model-behavior problem in isolation. The word "means" (from "column means") scored only 0.4 confidence against real documentation (below the 0.5 grounding threshold) and never resolved to `meanc` at all — the model was simply never given `meanc`'s real documentation as evidence, and filled the gap with its own unreliable general knowledge. Prompting alone (already tried in `v0.72.0`) could not fix this, because the retrieval layer never found the right evidence to hand the model in the first place.

**Panel-regression root cause**: identical class of problem. "panel"/"regression" as literal tokens scored only 0.4 confidence against real documentation, matching irrelevant archived files, while the real, documented command (`tscsFit`, in the `tsmt` package) shares no substring with either word — a pure vocabulary gap between how a user describes an operation and what the real function is named. Confirmed empirically in this milestone's own development (`command_doc_lookup.lookup("tscsfit", ...)` → confidence 1.0, exact match) that the real documentation was always present and retrievable — it was never being *asked for*.

Both failures are **retrieval/resolution failures**, not model-prompting failures — this is why this milestone's fix is a resolution layer and a generation gate, not a rewritten system prompt.

## 3. Function/concept resolution

`resolve_concepts(question, *, docs_root_str)` returns one `FunctionResolution` per candidate token (literal `EXACT_SYMBOL` matches, exactly as `v0.72.0`'s inline loop did) plus one per successfully-verified alias-phrase match (`ALIAS_OR_DESCRIPTION`). Evidence source: a small, explicit, human-curated `_CONCEPT_ALIAS_INDEX` (5 entries, covering `meanc`/`stdc`/`vec`/`inv`/`tscsfit`), each verified against real local GAUSS documentation content in this milestone's own development session before being encoded — every entry's `evidence` string quotes the real documentation it was checked against. Every resolution is independently re-verified again, at call time, against the CALLER's own configured `docs_root` — the index only ever proposes a candidate to check, never trusted as authoritative by itself. Match types: `EXACT_SYMBOL` (literal token), `ALIAS_OR_DESCRIPTION` (resolved concept). Statuses: `RESOLVED`, `AMBIGUOUS` (multiple similarly-scored real candidates — a genuine, high-confidence tie, not low-confidence noise), `UNRESOLVED` (honestly reported, never silently dropped). Example mappings: "column means"/"average each column"/"compute column averages" → `meanc`; "invert a matrix" → `inv`; "panel regression"/"pooled time series cross section regression" → `tscsfit`.

## 4. Grounding integration

`ground_multi(...)` now delegates all token/phrase resolution to `resolve_concepts(...)`, merging literal, resolved-concept, and recent-topic-fallback sources into one `GroundingBundle`, bounded to `MAX_GROUNDING_SOURCES = 4`, deduplicated by resolved symbol (a literal exact match always wins over a redundant alias match for the same symbol). Provenance is tracked per source via a new `GroundingSource.origin` field (`"literal"` / `"resolved_concept"` / `"recent_topic"`). A new `GroundingBundle.ambiguous_topics` field and `resolutions` field (the full list of `FunctionResolution`s) preserve complete decision provenance for the generation gate and for future review.

## 5. Generation gate

`compute_generation_gate(bundle) -> GenerationGateResult` is a pure function of `GroundingBundle`'s own already-computed evidence — no I/O, no model call, deterministic. Policies: **`FULL`** (every referenced topic grounded — generate normally), **`SUPPORTED_ONLY`** (some grounded, some not — generate only the supported portion, computed identically to `v0.72.0`'s own `PARTIALLY_GROUNDED` prompting, now formalized as an explicit policy), **`CLARIFY`** (genuine ambiguity — takes priority over the other two; the provider is never called, a fixed message names the real candidates and asks which was meant), **`BLOCK`** (no evidence at all — the provider is never called; a fixed, honest message is returned). `ConversationEngine.ask(...)` computes the gate immediately after grounding and BEFORE constructing any provider message for `Intent.CODE_GENERATION` turns; `BLOCK`/`CLARIFY` return directly, confirmed live (Section 8) to never reach `self.provider.complete(...)`.

## 6. Post-generation symbol check

`check_generated_symbols(code, *, supported_symbols)` extracts call-shaped identifiers (`name(`), skipping any line beginning with a verified GAUSS language-construct keyword (`if`/`for`/`do`/`proc`/etc. — verified via real GAUSS execution in this milestone's own session, not from memory) so a loop variable is never mistaken for a function call. A symbol is flagged `unknown_call_symbols` only when it is neither a grounded/resolved topic (including, after a live-found fix, any identifier appearing in that topic's own retrieved documentation content — e.g. `invpd`, documented alongside the resolved `inv`), a small explicitly-verified common-builtin set (`rows`/`cols`/`zeros`/`ones`/`rndu`/`rndn` — the last two added after a live false positive), nor plausibly assigned-to or `proc`-defined in the same code (classified `user_defined_or_ambiguous_symbols` instead). Intentionally NOT checked: variable semantics, dimension correctness, methodological appropriateness, or anything requiring real execution — this is explicitly not a compiler. False-positive risk is real and was directly observed and reduced twice during this milestone's own live testing (Section 8); it is not claimed to be zero.

## 7. Exact regressions

**Column means**: "Calculate the column means." now resolves `meanc` (confirmed both in automated tests — `test_76`, `test_76b` — and live against the real model — `63.1`, `63.2`, `63.3`). Generated code uses `meanc`. When the model was deliberately forced (via a canned fake-provider response) to still emit `colmean`, the post-generation check correctly flagged it (`test_76`) — the fix addresses disclosure/resolution honesty and detectability; it does not claim to have made the underlying model incapable of hallucinating.

**Panel regression**: live-tested twice. With authoritative documentation configured (`tscsFit`), the real model generated the real, documented call signature (`tscsFit(dataset, formula, grp, tsc)`) instead of `62.7`'s fabricated `panel`/struct-field pattern (`63.5`). Without any panel-estimation documentation configured, generation is deterministically `BLOCK`ed before the model is ever consulted (`test_77`, and live scenario `63.10` for a different fully-ungrounded request using the same policy).

## 8. Live Ollama validation

**Model**: `qwen2.5-coder:7b`. **Environment**: the same real, locally running Ollama installation validated in `v0.71.0`/`v0.72.0`. **Scenario count**: ten (`63.1`-`63.10`), all Passed (scores 3.6-4.0), real transcripts in `evaluations/runs/2026-09-10-code-assistant-grounding-gated-generation-run-*.md`.

**Gate decisions observed live**: `FULL` (63.1, 63.2, 63.3, 63.5, 63.6, 63.9), `SUPPORTED_ONLY` (63.4, 63.8), `CLARIFY` (63.7), `BLOCK` (63.10).

**Provider calls avoided**: confirmed for both `63.7` (CLARIFY) and `63.10` (BLOCK) — each returned in a fraction of a second against a real, reachable Ollama service, in stark contrast to every genuinely-answered scenario's multi-second-to-tens-of-seconds real inference latency, direct behavioral proof the provider was never invoked.

**Hallucinations**: one subtle, confirmed hallucination even in an otherwise fully successful scenario — `63.5`'s `tscsmtControl()` (the real constructor is `tscsmtControlCreate()`), caught by the post-generation checker.

**Unknown symbols / false positives found and fixed live**: `rndu` (63.1, fixed by allowlisting a verified-real builtin), a QA-classified hallucination the checker initially missed entirely (63.4, fixed by making the check intent-independent), `invpd` (63.6, fixed by scanning retrieved content for companion symbols). **False negatives**: none confirmed — every hallucination encountered live was either disclosed by the pre-generation gate, caught by the post-generation checker, or both.

## 9. Real GAUSS validation

Three FULL-gated, live-generated examples were executed via `tgauss.exe -b`: the `meanc` example from `63.1`/`63.2` (correct real column means of a random matrix), the `reshape`+`meanc` example from `63.3` (exact expected values: 4, 5, 6, 7, 8, 9), and the `invpd` example from `63.6` (executed without error; one minor generated-example-quality issue disclosed: the example matrix was not actually symmetric, which `invpd` is documented to require, though GAUSS did not raise an error). ## 13. Product impact

**Yes, grounding-gated generation materially reduced unsupported GAUSS syntax generation compared with `v0.72.0`**, with direct, observed evidence: both exact `v0.72.0` failure prompts, re-run against the same real model, now produce real, documented syntax instead of fabricated syntax (Section 7). Beyond the two headline fixes, the post-generation checker caught a THIRD, previously-unknown hallucination (`tscsmtControl`) in a scenario that otherwise looked fully successful — evidence the checker adds real value beyond the two known regressions it was built to catch. This is a small sample (ten live scenarios) and this claim should not be overstated statistically, but every scenario where evidence existed and was retrieved produced correct syntax, and every scenario where it didn't was either honestly blocked or the resulting hallucination was caught and disclosed.

## 14. Remaining limitations

- **Retrieval coverage remains bounded.** The concept-alias index has 5 entries; a real operation not in it and not literally named will not resolve, exactly as before.
- **The post-generation checker is conservative, not exhaustive** — it catches obvious hallucinated function calls, not semantic or dimensional errors (the `invpd` non-symmetric-matrix example in Section 9 is real evidence of this).
- **Ambiguity resolution depends on `command_doc_lookup`'s own scoring** producing a genuine near-tie; most real single-topic questions will not trigger `CLARIFY`.
- **Model dependence remains real** — `qwen2.5-coder:7b` still hallucinates when ungrounded; this milestone makes that harder to act on, not impossible to attempt.
- **Local hardware/Ollama dependence, no execution, no autonomous debugging, no file editing, and `docs-root` dependency** are all unchanged from `v0.71.0`/`v0.72.0`.
- **Anthropic remains not live-network-tested**, unchanged.

## 15. Recommendation

The project is ready for **human alpha testing of grounding-gated code generation** — the architecture demonstrably reduces, with direct live evidence, the exact class of failure the previous milestone disclosed, while preserving every existing safety boundary unchanged (zero diff on core pipeline modules). **Do not begin the next milestone automatically** — a future milestone's scope (e.g. controlled tool orchestration or an explicit, approval-gated execution handoff) should be a deliberate decision informed by this report and the real transcripts in `evaluations/runs/2026-09-10-code-assistant-grounding-gated-generation-run-*.md`, not an automatic continuation.
