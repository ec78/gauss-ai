# v0.9.0 Readiness Checklist

This checklist audits whether the repository is close to tagging `v0.9.0` - Second Operational Expert and Multi-Expert Routing. It is an audit record only; it does not tag a release.

## Release Goal

`v0.9.0` operationalizes a second expert, the Econometrics Expert, and extends expert routing from single-expert GAUSS routing to multi-expert routing across four cases: GAUSS-only, Econometrics-only, Both, and Neither. It proves the operational expert interface generalizes beyond the GAUSS Language Expert and that implementation correctness and methodological correctness can be routed and evaluated separately.

## Important Findings

- **16.4** found no verified GAUSS panel-estimation command in the inspected command categories (`experts/gauss-language/COMMAND_CATEGORIES.md`'s Panel Data category lists only data-management utilities — `pdLag`, `pdBalance`, `pdSummary`, `pdSort`, etc. — no fixed/random-effects estimation command). Verified panel coverage currently supports panel data-management, not a confirmed estimation command. This is non-blocking but is tracked for future command coverage (see Non-blocking Follow-ups and `KNOWN_LIMITATIONS.md`).
- **16.7** required live official GAUSS `glm` documentation (`docs.aptech.com/gauss/glm.html`) because no local schema-aligned `glm` evidence file existed. The fetched content was independently verified against the task's supplied facts rather than trusted at face value, and it confirmed them. This is non-blocking but suggests `glm` should be added to local schema-aligned evidence coverage in a future milestone.
- These findings reinforce the evidence-boundary design established across `v0.8.0`-`v0.9.0`: a lack of GAUSS command evidence does not prevent the Econometrics Expert from giving methodological guidance, and methodological plausibility never justifies inventing GAUSS implementation syntax. Both findings are examples of the system correctly disclosing a gap rather than papering over it.

## Remaining Limitations

- Multi-expert routing is a documentation/checkable workflow, not runtime instrumentation.
- Only two experts are operationalized: the GAUSS Language Expert and the Econometrics Expert.
- The Software Engineering, Documentation, and Education experts remain narrative-only.
- Manual evaluation still determines whether routing occurred; there is no automated multi-expert test harness.
- No full runtime multi-expert orchestration exists.
- No automated conflict-resolution engine exists beyond the documented coordination rules — surfacing tension between the two experts' conclusions is a response-writing responsibility, not an automated check.
- GAUSS command evidence remains entirely separate from econometric methodological context; meeting one is never sufficient to satisfy the other.
- Schema validation still does not prove GAUSS semantic correctness or execution.
- Local evidence coverage is still incomplete; `glm` is not yet represented as a schema-aligned evidence example.
- Verified native GAUSS panel-estimation command coverage remains unresolved — only panel data-management utilities are currently confirmed.
