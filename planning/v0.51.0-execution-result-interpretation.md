# v0.51.0 - Execution Result Interpretation

## Purpose

Teach the GAUSS Code Assistant to explain existing execution evidence after a run has completed, failed, timed out, or been blocked.

This milestone starts the transition from "execution framework" toward "reasoning assistant" without adding autonomous debugging. Interpretation is deterministic and evidence-bound.

## Implemented Components

- `scripts/gauss_execution_interpreter.py`
  - Defines `ExecutionEvidence`.
  - Defines `ExecutionInterpretation`.
  - Provides `interpret_execution(...)`.
  - Never launches GAUSS, edits code, retries execution, or reads workspace files.
- `scripts/gauss_error_catalog.py`
  - Defines `GaussErrorCategory`.
  - Defines `GaussErrorCatalogEntry`.
  - Provides catalog lookup helpers.
  - Keeps GAUSS-specific error knowledge outside the interpreter.
- `scripts/gauss_code_assistant_cli.py`
  - Adds the `interpret` command.
  - Builds interpreter evidence from the adapter's existing `last_result`, process metadata, and captured stdout/stderr.

## Supported Classifications

- Blocked before launch.
- Successful execution.
- Syntax/parse error.
- Runtime computation error.
- Matrix-dimension runtime error.
- Timeout.
- Unknown failure.
- Fake/non-GAUSS runner result.
- Insufficient stdout/stderr evidence.
- Unknown GAUSS error code.

## GAUSS Error Catalog

Initial specialized entries:

| Error Code | Category | Phase | Notes |
|---|---|---|---|
| `G0105` | `parse_syntax` | `parsing` | Bad expression or missing arguments. |
| `G0036` | `matrix_dimension` | `runtime` | Matrix dimensions are incompatible. |
| `G0025` | `runtime_computation` | `runtime` | Undefined symbol. |

Unknown `G####` codes are preserved and classified as `unknown`. The interpreter does not infer a meaning for uncataloged codes.

## Truthfulness Boundaries

The interpreter may explain only what is supported by execution evidence.

It does not claim:

- which source line failed unless that line is directly supplied by evidence;
- how to rewrite GAUSS code;
- why a statistical model failed;
- whether a hypothesis is correct;
- that execution success proves syntax is generally valid;
- that execution success proves methodology or statistical validity.

`next_step` guidance is diagnostic only, such as inspecting stdout/stderr, reviewing the generated GAUSS script, or verifying matrix dimensions.

## CLI Behavior

`interpret` is available after `execute`.

If no execution result exists, the CLI reports:

```text
ERROR no_result: run 'execute' before interpreting execution evidence.
```

For existing results, the command prints:

- execution phase;
- launch status;
- completion status;
- failure type;
- GAUSS error code/category when available;
- confidence;
- user and technical explanations;
- likely location when evidence supports one;
- diagnostic next step;
- evidence limitations.

It also prints the boundary:

```text
INTERPRETER_BOUNDARY: No GAUSS launch, no retry, no code edit, no automatic file read.
```

## Out of Scope

- Autonomous debugging.
- Code repair.
- Automatic retry.
- Durable execution sessions.
- Additional GAUSS launches.
- Automatic file reading.
- Broad GAUSS error cataloging.
- Statistical or methodological validation.

## Readiness Classification

Ready for manual alpha testing of post-execution interpretation.
