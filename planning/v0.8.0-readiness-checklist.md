- **15.1** (GAUSS code generation activation) — Pass, 4.0 — `run-002`. Used real `olsmt.evidence.json` for a CSV-load-and-regress example; correctly used the documented CSV-direct-load capability and disclosed the evidence's truncation point.
- **15.2** (R-to-GAUSS translation / native procedure) — Pass, 4.0 — `run-005`. Translated R's `lm()`/`coef()`/`summary()` to `olsmt`, explicitly justified the native-over-manual choice, preserved uncertainty for unconfirmed `olsmtOut` fields.
- **15.3** (Cross-language string debugging) — Pass, 4.0 — `run-003`. Identified both the Python `.find()` syntax and `-1` sentinel as contamination, corrected to `strindx`/`0` using real evidence, included a two-sided validation check.
- **15.4** (`qnewtonmt` vs. `minimize` command selection) — Pass, 4.0 — `run-007`. Recommended `minimize` for bound-constrained optimization using both real evidence files, stated the deciding criterion explicitly, disclosed `qnewtonmt`'s truncated controls section, declined an unsupported deprecation or version claim.
- **15.5** (DataFrame vs. matrix design guidance) — Pass, 4.0 — `run-006`. Recommended DataFrame-then-matrix using `BODY_OF_KNOWLEDGE.md`'s decision table, identified a concrete transition point, declined to name exact syntax without retrieval.

- **15.7** (Non-GAUSS non-activation) — Pass, 4.0 — `run-001`. Drafted the requested changelog entry with zero GAUSS-specific reasoning or evidence requests, confirming non-activation is checkable from the absence of that machinery.

All 15.x Expert Routing prompts passed with 4.0 scores. No benchmark-wording mismatches were found in this category, unlike the 13.1/13.5 corrections needed during Evidence Schema evaluation.

## Remaining Limitations

- Expert routing is a documentation/checkable-workflow contract, not runtime instrumentation — no code parses or enforces these files at runtime.
- Only the GAUSS Language Expert is operationalized in `v0.8.0`.
- The Econometrics, Software Engineering, Documentation, and Education experts remain narrative-only.
- Manual evaluation still determines whether routing occurred; there is no automated expert-routing test harness.
- No full multi-expert orchestration exists (what happens when two experts' domains overlap on one task is out of scope).
- Evidence requirements still depend on retrieval/evidence files; expert profiles do not replace official GAUSS documentation.
- Schema validation still does not prove GAUSS semantic correctness or execution — this is unchanged by the expert layer.
