# v0.32.0 Readiness Checklist

## Release Goal

`v0.32.0` implements Increment 1 of Phase 3 of `planning/v0.31.0-runtime-orchestration-design.md`'s Implementation Phases: the first controlled, real connection between the canonical execution request, the runtime state machine, a new Helper Adapter, and the existing, verified `execute_gauss_code(...)` helper — entirely against fake/stubbed helpers, with real GAUSS execution remaining gated behind a separate, doubly-gated, explicitly opt-in mechanism.

`v0.32.0` Increment 1:

- Creates `scripts/gauss_execution_adapter.py` (the Helper Adapter).
- Integrates it into `scripts/gauss_runtime_orchestration.py` via a new `AdapterRunner` bridge.
- Extends `RunnerInput` (not replaces it) with `gauss_version`/`expected_input_files`/`required_packages`.
- Establishes the production-import boundary: only the adapter's `load_real_helper()` factory may import the real helper, lazily, and only via an explicit, separate caller action.
- Creates `scripts/test_gauss_execution_adapter_real.py`, a doubly-gated real-smoke-test harness.
- Adds and evaluates `33.x` benchmarks.
- Updates project documentation and tracking.

`v0.32.0` Increment 1 does **not**:

- Run real GAUSS, at any point in its own production.
- Invoke `gauss.exe` or `tgauss.exe`.
- Launch a subprocess.
- Import or call `execute_gauss_code(...)` outside the one sanctioned lazy factory, and never calls the callable that factory returns.
- Supply both real-smoke-test gates simultaneously.
- Enable script-path execution.
- Add automatic execution, automatic retries, or automatic reruns.
- Add network access, credential handling, or output-file content reading.
- Claim cross-process, crash-safe, or distributed exactly-once behavior.
- Claim cancellation terminates a synchronous process.
- Claim successful execution proves methodology.
- Modify `scripts/gauss_code_execution.py`, `schemas/gauss_code_execution.schema.json`, `scripts/gauss_environment_check.py`, `scripts/gauss_package_inspection.py`, workflows, agents, prompts, or `1.x`-`32.x` benchmarks.
- Wire anything into `workflows/code-assistant-response.md` or any agent.

## Artifact Summary

### Helper Adapter

**Path:** `scripts/gauss_execution_adapter.py`

**Purpose:** the single controlled boundary between orchestration and the execution helper. `GaussExecutionAdapter` (explicit, required `helper` argument), `AdapterRequest` (a narrow, self-contained 13-field projection), `AdapterOutcome`/`AdapterFailureCategory`, `HelperCallable` (a `Protocol` matching the real helper's verified signature), and `load_real_helper()` (the one lazy, explicit-only factory).

Covers: exact field projection into the helper's real parameters, explicit constants (`strict=True`, `allow_network=False`, `allow_file_write=False`), seven distinct pre-invocation guards (duplicate invocation, script-path, missing code, structural validity, unsupported executable, environment mismatch, missing package context), recognition of all seven verified `execution_status` values without inventing new ones, malformed-result and unrecognized-status handling, output-metadata-is-not-content preservation, exactly-once-per-instance invocation, no automatic retry, distinct helper-exception classification, unmodified raw-result retention, and secret/code-excluding safe summaries.

### Controller Integration

**Path:** `scripts/gauss_runtime_orchestration.py`

**Purpose:** bridges the Helper Adapter into the existing mock controller's `FakeRunner` boundary without changing the controller's own transition logic.

Covers: `AdapterRunner` (structurally satisfies `FakeRunner`; raises on an adapter-level pre-invocation rejection, which `invoke()` already classifies as `RUNNER_LAUNCH_FAILURE` — correct, since confirmation was already consumed by that point); an extended `RunnerInput` (`gauss_version`, `expected_input_files`, `required_packages` added). All 40 pre-existing tests pass unmodified; 20 new tests (41-60) exercise the identical scenario set through the adapter bridge.

### Real Smoke-Test Harness

**Path:** `scripts/test_gauss_execution_adapter_real.py`

**Purpose:** the doubly-gated mechanism through which any future real GAUSS invocation via this Helper Adapter would be authorized.

Covers: `gate_status(...)`/`should_run(...)` (pure, testable gate logic); `main()` requiring both `--run-real-gauss` and `GAUSS_AI_ALLOW_REAL_EXECUTION=1` simultaneously, skipping cleanly (exit 0, no GAUSS touched) whenever either is absent; platform verification (Windows only) and terminal-executable verification (`tgauss`/`tgauss.exe`, existing, non-GUI) performed only after both gates pass and before any invocation is attempted; a prominent notice printed the moment both gates are detected; a `--self-test` mode that verifies only the gating/preflight logic and never supplies both gates.

### `33.x` Benchmarks

**Paths:** `evaluations/benchmark-prompts.md`, `evaluations/benchmark-coverage.md`, `evaluations/runs/2026-07-19-code-assistant-helper-adapter-run-001.md` through `-030.md`

**Purpose:** validate Helper Adapter and controller-integration behavior — request projection, explicit constants, script-path/environment/executable/package-context preflight rejection, confirmation-consumption timing, all seven helper statuses, malformed-result handling, duplicate invocation, no-automatic-retry, rerun-as-new-request, both cancellation timings, downstream-failure evidence preservation, explicit real-helper selection, default-path safety, both real-smoke-test gates (individually and combined disclosure), single-process scope disclosure, and helper/schema-unchanged confirmation — without ever running real GAUSS or supplying both real-smoke-test gates simultaneously.

## Real Helper Adapter Integration Summary

- The Helper Adapter is the only permitted route from orchestration to the execution helper — no second call site exists.
- No shell-string construction anywhere in the adapter; only structured keyword-argument calls to the injected helper.
- Confirmation is consumed atomically with invocation authorization, unchanged by the adapter bridge.
- Exactly one invocation per confirmed request, within one Python process, one live controller instance, one in-memory registry — explicitly not a cross-process, crash-safe, or distributed guarantee.
- Script-path execution remains unconditionally blocked; a resolved path is never treated as proof of unchanged file contents.
- GUI `gauss.exe` is rejected at the adapter boundary, in addition to the helper's own independent refusal.
- Real-helper selection requires an explicit, separate call to `load_real_helper()`; omitting the `helper` argument to `GaussExecutionAdapter` is a hard `TypeError`, never a silent fallback.
- No automatic retry, no automatic rerun, anywhere in the adapter or its controller integration.
- Cancellation remains non-cooperative once a call is in flight; no claim of process termination is made anywhere.
- Successful execution is never treated as proof of methodological validity, anywhere in the adapter's or controller's data model.

## Production-Boundary Summary

- `scripts/gauss_code_execution.py` and `schemas/gauss_code_execution.schema.json` are unmodified — confirmed via `git status --short` throughout this milestone's work.
- The controller (`scripts/gauss_runtime_orchestration.py`) never imports `execute_gauss_code`, directly or indirectly — confirmed live: importing the controller never places `gauss_code_execution` in `sys.modules`.
- The adapter module (`scripts/gauss_execution_adapter.py`) never imports `gauss_code_execution` at module level — confirmed live (identical check).
- `load_real_helper()` is the one sanctioned import site, lazy (inside its own function body), and never called automatically by `GaussExecutionAdapter`'s own construction or by any default test.
- A missing helper dependency fails honestly (`ImportError`, with a clear message naming the missing module) — verified by simulating absence via `sys.modules["gauss_code_execution"] = None` without touching the real file.

## Remaining Limitations

- Real GAUSS execution through this Helper Adapter remains unverified — the doubly-gated harness exists but has never been run with both gates active.
- Cross-process, crash-safe, and distributed exactly-once behavior remain unimplemented and unclaimed.
- Script-path execution remains blocked; content-based fingerprinting remains an unresolved prerequisite for any future support.
- True cooperative cancellation remains unimplemented; a synchronous call, once started, cannot be interrupted.
- Output-file content reading remains unimplemented; only metadata is ever available.
- Cross-platform (macOS/Linux) and cross-version (GAUSS 24/25) behavior remain unverified.
- No user-facing wiring exists between this milestone's work and `workflows/code-assistant-response.md` or any agent.
- Production-scale reliability (durable persistence, invocation-record recovery after a crash) remains unaddressed, per `planning/v0.32.0-real-helper-adapter-scope.md`'s own Open Decisions.
