## Known Warnings and Strict-Mode Policy

Exactly 2 warnings exist across the whole evidence set, both on `olsmt.evidence.json`:
```
Unredacted local absolute path found at $.best_match.notes[0].
Unredacted local absolute path found at $.matches[0].notes[0].
```
Both are **confirmed false positives**: the flagged text is `olsmt`'s own official-documentation HDF5-URI usage example (`olsmt("h5://C:/gauss/examples/testdata.h5/mydata", formula)`), not a leaked local machine path. This has been independently verified multiple times across this milestone.

**Documented policy** (in `scripts/README.md` and cross-referenced in `schemas/README.md`): the default non-strict `validate_all_evidence.py` run is the `v0.7.0` release-health check and currently passes. `--strict` is *expected* to fail solely because of these two reviewed warnings — this is intentional and documented, not a blocker, and not something to suppress or hide. Improving the validator's path-detection heuristic (e.g., skipping matches inside recognized non-local URI schemes or literal code-block text) is tracked as future work, not required for `v0.7.0`.
