# v0.10.0 Readiness Checklist

## Release Goal

`v0.10.0` hardens the `v0.9.0` multi-expert/evidence system rather than extending routing or adding a new expert. It:

- Closes the local `glm` evidence gap that `v0.9.0`'s `16.7` evaluation had to work around with a live documentation fetch.
- Documents GAUSS panel-estimation coverage clearly, resolving the open question left by `v0.9.0`'s `16.4` evaluation.
- Adds a local evaluation tracking consistency guard so benchmark prompts, coverage rows, run files, and the run index stay consistent with each other going forward, instead of relying only on an evaluator's manual diligence.
- Validates all three of the above with the `17.x` Evidence Coverage and Tracking Guards benchmark category.

## Panel Coverage Summary

- **Verified:** `tscsFit`, from the commercial **TSMT** (Time Series MT) package — a genuine pooled time-series-cross-section regression estimator. Verified syntax: `tso = tscsFit(y, x, grp[, tsc])` / `tso = tscsFit(dataset, formula, grp[, tsc])`. It returns both fixed-effects (`tso.bdv`, `tso.fixedEffects`) and random-effects (`tso.bec`, `tso.randomEffects`) coefficient estimates from a single call. Real schema-aligned evidence exists and validates: `examples/retrieval/schema-aligned/tscsfit.evidence.json`.
- **Not found:** no dynamic-panel-GMM or Arellano-Bond-style command was found anywhere in the searched local docs. `lsdvFit` (also TSMT) remains explicitly **unclear** — its documented purpose is a generic autoregressive-error regression, not explicitly framed as a panel fixed-effects estimator, so it is not classified as a verified panel estimator.
- **Classification, to avoid conflation:**
  - Panel data-management/summary utilities (`pdSummary`, `pdLag`, `pdBalance`, and neighbors, base GAUSS) — prepare, reshape, balance-check, or describe panel data. Not estimators.
  - Panel tests/diagnostics — unit-root/cross-sectional-dependence tests (`breitung`, `ips`, `httest`, `cdtest`, TSMT) and Granger-causality tests (`panel_fisher`, `panel_surwald`, `panel_zhnc`, tspdlib). Test a statistical property; do not fit a model.
  - Panel regression estimation — only `tscsFit` is verified in this category.
- **Package dependency:** TSMT is separately licensed (not bundled with base GAUSS) and requires GAUSS/GAUSS Engine v25+. This must be stated explicitly whenever `tscsFit` is recommended.
- Exact panel-estimation syntax must not be invented for any scenario `tscsFit` does not cover (for example, dynamic panel GMM) — an honest "not found, here's what was checked" is the correct and accepted answer for that gap.

## Important Findings

- The `glm` local evidence gap identified during `v0.9.0`'s `16.7` evaluation is closed: `glm.evidence.json` now exists locally and validates.
- Panel-estimation coverage is now documented from a systematic audit rather than guessed at or left as an open question: `tscsFit` is verified; everything else checked is correctly classified as data-management, a diagnostic test, or unresolved.
- The tracking guard correctly distinguishes errors (structural, always block default mode) from warnings (advisory, only block `--strict`) — confirmed directly from its source and from live runs throughout the `17.x` evaluations.
- A default `PASS` does not mean zero warnings — the `17.x` evaluations exercised this directly, including a transient state with as many as 12 warnings mid-batch (documented historical warnings plus temporary "not yet tracked" states), all correctly reported rather than hidden.
- A `--strict` failure is expected and will persist as long as the two historical warnings remain undocumented-away — this is intended behavior, not a defect to fix before release.
- `17.5` and `17.6` surfaced a benchmark-authoring artifact, not a system defect: their own "Expected behavior" text hardcoded specific counts (a warning count, and prompt-ID/coverage-row counts) that were only accurate before Prompts `17.1`-`17.6` themselves existed or were tracked. Both evaluations correctly reported the true live tool output instead of reciting the stale figures. Recommendation for future benchmark authoring: avoid hardcoding volatile repository counts in expected-behavior text unless the benchmark is explicitly scoped to a fixed, frozen repository state.
- This audit independently found and fixed additional stale wording beyond what the `17.x` evaluations covered: `README.md` and `ROADMAP.md` still described `v0.9.0` as the current/in-progress milestone, and `KNOWN_LIMITATIONS.md`'s header still said "as of `v0.9.0`" despite already containing `v0.10.0`-era content (the `glm` and `tscsFit` findings). All three have been corrected as part of this task (see Task 3 audit result below).
- This audit also found, but per the task's constraints did **not** modify, stale wording in `experts/econometrics/OPERATIONAL_PROFILE.md` (an operational profile, outside this task's editable scope): it still describes multi-expert routing in `workflows/expert-routing.md` as "not yet extended," "not yet built," and "not yet added" (lines referencing a `v0.9.0` follow-on task), even though multi-expert routing was completed and evaluated in `v0.9.0`. This is a real, pre-existing staleness issue and is recorded as a non-blocking follow-up below rather than fixed in this task.

## Remaining Limitations

- No GAUSS execution engine exists; nothing in this milestone changes that.
- Schema validation is structural, not semantic or execution validation — a schema-valid evidence file is not proof of correct or current GAUSS behavior, nor that any code ran.
- `--strict` mode still fails on the two documented historical tracking warnings, and on the two documented HDF5-URI evidence path-warning false positives (`olsmt`, `glm`) — both are accepted, reviewed exceptions, not defects to clear before tagging.
- Multi-expert routing remains a documentation/evaluation-driven contract, not runtime orchestration — no code parses or enforces `workflows/expert-routing.md` or the operational profiles at runtime.
- Only the GAUSS Language Expert and the Econometrics Expert are operationalized; the Software Engineering, Documentation, and Education experts remain narrative-only.
- Panel-estimation support remains limited to what was actually verified (`tscsFit`); no other panel-estimation command should be assumed to exist.
- The evaluation tracking guard is local-only; there is no CI integration yet.
- Benchmark authoring can still become stale if expected-behavior text hardcodes volatile repository counts instead of describing behavior in relative/qualitative terms.

## Blockers

None. All required deliverables are complete, all `17.x` evaluations passed at 4.0, both validators report their expected default/JSON results, and both strict-mode failures are the same previously-documented, reviewed exceptions rather than new or unexplained failures.
