# v0.93.0 — Result Shapes and Members: Design

Status: **proposed** (2026-11-09), waiting on the §8 decisions. Baseline for every probe and comparison: HEAD `fb5040e` (`v0.92.1` plus its publication record), with the docs copy fetched on 2026-10-23 and this machine's GAUSS 26.1.4 installation.

The fourth milestone under v0.89's decision 10 = **B** (widen deterministic coverage within the existing constraint). It takes up live evaluation 83.x's finding 3 (`planning/v0.92-installed-libraries.md` §12.4) and 82.x's finding 2 (`planning/v0.91-expression-categories.md` §12.4).

## 1. Why

v0.92.0 let package code reach the handoff, and 83.x showed what keeps everyday GML code from getting there. The cause is no longer the library but how GML results are *used*:
- `{ y_train, y_test, X_train, X_test } = trainTestSplit(y, X, 0.7);` leaves all four names untraced (83.3, 82.13);
- `sumc(mdl.assignments .== cluster_id)` refuses its member operand (83.5);
- `lassoFit(y, X, 0.1)` with `y = X * b + rndn(500, 1)` stays unknown because `lassoFit.rst` documents `y` as an `Nx1 vector`, and a numeric expression is only "numeric" (82.x finding 2, the `vector` half of decision 1(c)).

All three are safe-direction gaps: the code is held at `review_required`, never passed wrongly. But they are where a client starts rewriting correct code to get a run (82.2's `sqrt` → `.^ 0.5`, 82.4's sort-and-slice).

| # | Item | Effect today | Measured (§2.1) |
|---|---|---|---|
| A | A `vector` parameter can never be confirmed by a traced call or an expression | `lassoFit(y, …)`, `selif(x, x .> 0)` stay review_required | 26 + 7 gaps; 12 programs have no other gap |
| B | A structure member is never an operand | `mdl.assignments`, `out.par` refuse | 27 gaps; 7 programs have no other gap |
| C | A name assigned by `{ … } = f(...)` is never traced | every GML train/test workflow | 107 gaps in 38 programs (all from three split functions) |

Goals:
- each of A-C gets a category from **documented or GAUSS-verified evidence**, never from a guess about values;
- the new categories, like every derived category since v0.81.0, can **MATCH but never MISMATCH**, so they can only remove false gaps, never add a block;
- nothing reaches `handoff_candidate` that is I/O, and every program that moves there is run in GAUSS.

Constraints (all from `CLAUDE.md`):
- deterministic: shapes come from documented `:rtype` text, documented member tables, literal arguments and fixed operator rules; no model, no score, no evaluation;
- every scan reads `lex_gauss_source(...)`'s masked view and `source_statements(...)`;
- preconditions, the syntax rules, the system-statement and dataset-argument registries, the library boundary, the generation gate and grounding are unchanged;
- documentation extraction changes (B's member tables, A's `:rtype` dimensions) get the full before/after diff across all published pages.

Out of scope:
- computing any value or any dimension other than "this dimension is 1";
- member *writes* (`ctl.maxIters = 5;`): still refuse tracing, as today;
- user-defined procedures' returns, and multiple returns of a procedure the docs do not describe;
- the typed-declaration initializer (v0.91 finding 3) unless decision 4 adds it;
- checking that a member name exists (`G0504`); a later item (see §5).

The not_ready count matters because a client writing the same workflow with simulated data hits exactly these gaps (83.3-83.5).

### 2.2 Item A: where "vector" is lost

- **A traced call keeps only its documented category.** `rndn.rst`'s first `:rtype` is `RxC matrix`, so `y = rndn(500, 1);` is `matrix`, and against `Nx1 vector` it is `return_type_imprecise`. But the dimensions are named after the function's own parameters (`r`, `c`), and the call passes the literal `1`. **72 pages** document a first return whose dimensions name a parameter: `rndn`, `rndu`, `zeros`, `ones`, `reshape`, `matalloc`, `matinit`, the `rnd*` family (`r x c`, `rows x cols`), `eye` (`NxN`), and others whose shapes are counts (`acf`: `Kx1 vector`).
- **Element-wise expressions over one non-scalar keep its shape** (ve1): with a 5×1 `x`, `(x .>= 0) .and (x .< 1)` and `2 * x - 1` are 5×1. But `x .> x'` is 5×5 (broadcasting). So a `vector` survives an expression only when **every non-scalar operand is the same traced name** with no transpose, and the operators are element-wise or scalar ones (`* /` with a scalar side).
- **The documented `vector` parameters hit most:** `selif`/`delif`'s `e` (16), `quantile`'s `e` (6), `cusum`/`rolling`/`tarTest`'s `yt` (10), `lassoFit`/`arimaFit`/`dfgls`'s `y`, `fcMetrics`' `actual`, `findIdx`'s `cond`.

### 2.3 Item B: documented members

- **Member tables are documented for result structures.** 47 pages carry an inline table for their `:return` structure (458 rows; 410 begin with a classifiable type), and 56 more include one from an `include/` file (`tsmt/include/garchestimation.rst`). Three layouts: `csv-table` rows (`"mdl.assignments","Nx1 matrix, …"`), `list-table` rows (`* - gout.aic` / `- scalar, …`), and parenthesized types (`"mdl.beta_hat","(*P x nlambdas matrix*) …"`).
- **They match GAUSS** for the probed case (km1): `mdl.assignments` is 50×1 and `mdl.centroids` 3×2 after `kmeansFit(X, 3)` with 50×2 `X`, as `kmeansFit.rst` documents.
- **They are not always right.** 82.x found `gmmfit.rst`'s `parEst`/`numParms` wrong (`G0504`). A wrong member name fails in GAUSS, in memory; this milestone never trusts a member's *existence* for safety, only its category for a MATCH.
- **The producer must be traceable:** `mdl` governed by exactly one `mdl = f(...)` whose `:rtype` is `struct` and whose page carries the table. A declaration `struct kmeansModel mdl;` is not a write; any member write to `mdl` refuses, as today.

### 2.4 Item C: multiple returns

- **138 of the 184 pages with a `{ … } = f(...)` form type every output** by name (`:return name:` / `:rtype name:`); 38 type some, 8 none.
- **But every multiple-return gap in the corpus comes from two of those 8 untyped pages:** `trainTestSplit` (103) and `splitData` (4). The third untyped split function, `cvSplit`, documents the same four outputs. So typing outputs by their `:rtype` alone would move almost none of the real cases.
- **GAUSS shows what the split functions return** (tt1, tt2, sd1): every output keeps its input's column count and is a numeric matrix (type 6). `y` 100×1 → `y_train` 70×1; `X` 100×3 → `X_train` 70×3; a two-column `y` gives two-column outputs; `splitData(X, 0.7)` keeps `X`'s three columns. Their pages say so in prose (`X_train`: "(*train_pct* \* *N*) x *P* matrix"; `y_test`: "the remaining observations from the original *y*"), but not as a `:rtype`.

## 3. Proposed design

### 3.1 Item A: documented dimensions and vector-preserving expressions

- **Documented dimensions.** The `:rtype` reader keeps, alongside the category, the shape text's two dimension tokens when it is `<a> x <b>` (`RxC`, `r x c`, `rows x cols`, `Nx1`). At a call, a dimension token that names one of the function's own parameters, given a literal `1` (or a name traced to the literal `1`), is 1. So `rndn(500, 1)` is a column vector (`vector`), `ones(1, k)` a row vector, `zeros(1, 1)` a scalar; and a documented `Kx1`/`Nx1` return is a vector whatever the arguments. A dimension that is not the literal 1 decides nothing, and the category stays the documented one.
- **Vector-preserving expressions.** `infer_expression_category(...)` returns `vector` (instead of `matrix`) when every non-scalar operand is the **same name**, untransposed and unindexed, traced to `vector`; every other operand is a numeric scalar (literal or traced); and every operator is element-wise (`.* ./ .^ + - .== .> … .and .or .not`), a comparison, or `* /` with a scalar side. Concatenation, transpose, matrix product between non-scalars, and indexing keep `matrix`.
- **Origin:** both are `DOCUMENTED_RETURN` / `EXPRESSION_CATEGORY` as now, so they MATCH but never MISMATCH: a `vector` where the docs say `scalar` stays `return_type_imprecise`, never a block.

### 3.2 Item B: member operands

- **Member tables.** The docs extraction reads each page's result-structure table (the three layouts in §2.3, plus an `.. include:: include/<file>.rst` in the Outputs, resolved inside `docs_root` only) into `{member: categories}` for the `:return` structure. A row whose type text does not classify is left out, never guessed.
- **Operands.** In an expression, and as a whole argument, `name.member` is an operand when `name` is governed by exactly one plain `name = f(...)` (the existing `_governing_assignment`, which already refuses on any member write), `f`'s first `:rtype` is `struct`, and `f`'s table lists `member`. Its category is the documented one; `name.member[., k]` and other indexing keep the v0.91 indexing rule (numeric operand, numeric result). Anything else refuses, as today.
- **Origin:** a new `ArgumentOrigin.DOCUMENTED_MEMBER`, MATCH-never-MISMATCH.

### 3.3 Item C: multiple returns

- **Typed outputs.** `_governing_assignment` stops refusing on `{ a, b, … } = f(...)` when the statement is plain and top-level, `f` is a documented function, and the target list matches one documented form's output list in length. The target at position *i* gets the category of that form's *i*-th output, by its `:rtype name:` line. An untyped output stays untraced (`return_type_undocumented`, naming the output).
- **The split functions (decision 1).** `trainTestSplit`, `splitData` and `cvSplit` document no output type. Option (b) adds a curated, cited registry, like the dataset-argument registry: each output is "rows of input *j*", so it takes input *j*'s traced category (`vector` stays `vector`, `matrix` stays `matrix`; a scalar or unknown input gives unknown). Evidence per entry: the page's prose plus the §2.4 spot checks, recorded in the entry. Option (a) leaves them untyped and reports the pages to Aptech.
- **Origin:** `DOCUMENTED_RETURN` (typed) or a new `ArgumentOrigin.REGISTERED_RETURN` (registry), both MATCH-never-MISMATCH. The precondition tracer never reads either: a split output's values are runtime-dependent.

### 3.4 What does not change

The generation gate and grounding; preconditions and their checkers; the syntax rules; the system-statement, dataset-argument and library rules; the execution handoff, its digest and prompt; the MCP tool surface. Only `parameter_role_check` coverage can move.

Out of scope: §1's list.

## 5. Known limitations this design accepts

- **Only "a dimension is 1" is ever computed.** `rndn(n, 1)` with untraced `n` is still a vector (the second dimension decides it), but `rndn(n, k)` with `k` traced to 1 only through an expression is `matrix`.
- **A member's documented category is trusted for a MATCH, its existence is not checked.** A misspelt or wrongly documented member (`gmmfit.rst`) still fails only in GAUSS (`G0504`), as today. A deterministic member-existence check is a candidate for later.
- **Member tables in other layouts are not read** (a member described only in prose stays unknown).
- **Split-function outputs follow the registry, not the docs**, under decision 1(b): if Aptech changes a split function's behaviour, the registry entry is wrong until updated (the same trade as the dataset-argument registry).
- **`kmeansFit`'s `X`/`X_train` mismatch** (83.x finding 4) is left to Aptech: its `:type` is never matched.

## 6. Testing plan

### 6.1 Automated tests (synthetic fixtures, network-free)

Every new test except invariance checks is confirmed failing against HEAD `fb5040e`.
- **`test_gauss_pre_execution_validation.py`:** documented dimensions (`RxC` with a literal and a traced `1`, `rows x cols`, `Nx1`, a non-1 literal, a dimension that names no parameter); vector-preserving expressions (single operand, repeated same name, scalar sides, and every refusal: `x .> x'`, two different vectors, `~`, `x * y`, indexing); member operands (each table layout, an include file, an unknown member, a member write, a two-assignment producer, a non-struct producer); multiple returns (typed by name, a length mismatch, an untyped output, a nested block); the registry (each entry, a scalar input, an unknown input); every new origin MATCHes and never MISMATCHes; lexical discipline (a member or brace list inside a string or comment is never read).
- **The docs-lookup tests:** member-table extraction per layout, include resolution confined to `docs_root`.
- **`test_gauss_conversation_engine.py`:** 83.3- and 83.5-shaped programs on fixtures reach `handoff_candidate`; the same with a member write or a two-vector broadcast stay review_required.
- **Full suite** (49 files), `check_release_readiness.py` and the CI matrix.

### 6.2 Extraction diff

Before/after across all 1,826 published pages: every changed signature, return category or dimension pair, and every member table read (page, structure, row count, unclassified rows). Each of the 72 dimension-naming `:rtype` pages reviewed individually.

### 6.3 Verdict diff

The 1,410-program corpus plus generated probes for each §2 shape, through `validate_code` at HEAD and on the working tree, each in its own process. Every upward move (`review_required` → `handoff_candidate`) listed and run in GAUSS from its own scratch directory; any `not_ready` change explained; no downward move expected (none of A-C can add a block).

### 6.4 Gate

No grounding code changes, so the gate diff is not required; the gate questions are re-run once to confirm.

## 8. Decisions needed

1. **The split functions:** (a) leave them untyped and report the pages to Aptech; or (b) a curated, cited "rows of input *j*" registry for `trainTestSplit`, `splitData` and `cvSplit` (recommended: they are the whole of item C in practice, and §2.4's spot checks are direct evidence).
2. **Member tables from `include/` files:** read them (recommended: `tsmt` and other packages keep their result tables there; resolution stays inside `docs_root`)?
3. **Vector-preserving expressions** (§3.1, second bullet) in this milestone, alongside documented dimensions? (Recommended yes: `selif(x, x .> 0)` is the commonest single gap.)
4. **Also trace a typed declaration with a literal initializer** (`string names = { "a", "b" };`, v0.91 finding 3: 35 untraced names, 11 in review_required programs)? Recommended as a separate small item, not in this milestone.
