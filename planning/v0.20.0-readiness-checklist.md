## Release Goal

`v0.20.0` defines the first GAUSS tooling capability area: environment detection. It is intentionally non-implementation work — it specifies, structures, exemplifies, and evaluates expected assistant behavior for a future GAUSS environment detection tool, following the strategy laid out in `planning/v0.19.0-gauss-tooling-strategy-and-execution-modes.md`.

`v0.20.0`:

- Creates the `gauss_environment_check` tool specification.
- Creates the result schema.
- Creates validated example outputs.
- Adds and evaluates `26.x` response-behavior benchmarks.
- Documents graceful fallback expectations.
- Keeps Advisory Mode fully supported.

`v0.20.0` does **not**:

- Implement actual environment detection.
- Inspect installed packages.
- Run GAUSS code.
- Activate Execution Mode.
- Implement runtime orchestration.

### Result Schema

**Path:** `schemas/gauss_environment_check.schema.json`

**Purpose:** Validates structured output for the future environment check tool.

- Draft 2020-12, matching `schemas/command_lookup_evidence.schema.json`'s existing repository convention.
- Fifteen required top-level fields plus one optional (`raw_detection_details`).
- `detection_status` enum: `found`, `not_found`, `ambiguous`, `inaccessible`, `error`, `unknown`.
- `operating_mode_recommendation` enum: `advisory`, `verified_knowledge`, `execution_candidate`.
- Tri-state (`true`/`false`/`"unknown"`) fields: `installed`, `accessible`, `can_execute_gauss_code`, and each candidate's `accessible` field.
- `allOf`/`if`/`then` detection-status consistency constraints (e.g., `found` requires `installed: true`, `accessible: true`, `operating_mode_recommendation: execution_candidate`, and a non-null `executable_path`; `not_found` requires the inverse).

## Detection States

| State | Meaning | Operating Mode Recommendation | What the Assistant Must Not Claim |
|---|---|---|---|
| `found` | A plausible GAUSS executable was found and appears accessible; ambiguity resolved. | `execution_candidate` | No code has run; no package inspection has occurred; no syntax or methodology has been validated. |
| `not_found` | No plausible GAUSS executable is found. | `advisory` | That code ran, or that GAUSS is unavailable for any reason beyond "not found." |
| `ambiguous` | Multiple plausible executables found; cannot safely choose. | `advisory` | That any one candidate was silently selected or is safe to use. |
| `inaccessible` | A path exists but cannot be accessed or queried (permissions, licensing, or execution restrictions). | `advisory` | That GAUSS is "definitely not installed" — inaccessible is a distinct, less certain state. |
| `error` | Detection failed unexpectedly. | `advisory` | That the failure means GAUSS is missing, or that execution is safe. |
| `unknown` | Environment cannot be checked, platform unsupported, or detection inconclusive. | `advisory` (or `verified_knowledge`) | Certainty in either direction about installation. |

Only `found` recommends `execution_candidate`. All other states recommend Advisory Mode. `execution_candidate` is not Execution Mode — it is a prerequisite signal only, per `tools/gauss_environment_check.md`'s Operating Mode Relationship section.

## Operating Mode and Fallback Summary

- Advisory Mode remains the assistant's current behavior and its fallback in every non-`found` state, and in `found`-but-inaccessible or `found`-but-ambiguous partial results.
- Verified Knowledge Mode remains available whenever command evidence supports a claim, independent of GAUSS's local availability.
- `execution_candidate` is only a future-readiness signal.
- Execution Mode does not exist yet — no execution tool has been built.

State:

- GAUSS not detected must not break the assistant.
- The assistant can still write, explain, review, document, teach, and product-frame GAUSS work without execution.
- The assistant must label unexecuted code and expected outputs clearly.
- Detection does not imply execution.
- `execution_candidate` does not imply execution occurred.

## Expert Boundary Summary

- The GAUSS Environment Check supports implementation-environment awareness but does not replace GAUSS command evidence.
- Detecting GAUSS does not validate syntax.
- Detecting GAUSS does not validate package availability.
- Detecting GAUSS does not validate statistical methodology.
- Detecting GAUSS does not validate maintainability/design quality.
- Detecting GAUSS does not validate documentation quality.
- Detecting GAUSS does not validate education/learning design.
- Detecting GAUSS does not validate product/user value.
- Even future successful execution would not prove statistical validity or product value.

## Important Findings

- `v0.20.0` successfully defines the environment-detection contract without implementing execution.
- The schema and examples make future implementation testable — any real implementation can be validated against the same schema and compared to the same expected-shape examples.
- The `26.x` benchmarks protect against the highest-risk overclaims this capability area introduces: detected means executed; installed means syntax is valid; installed means methodology is valid; GAUSS-unavailable means the assistant is useless.
- Advisory Mode remains fully intact and was directly exercised (not just asserted) by `26.2` and `26.6`.
- `execution_candidate` is now explicitly defined, tested, and documented as a non-execution state.
- The next implementation milestone can start from a safer, pre-validated contract rather than inventing detection semantics during implementation.
