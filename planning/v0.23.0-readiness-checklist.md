# v0.23.0 Readiness Checklist

## Release Goal

`v0.23.0` implements the read-only GAUSS package inspection helper based on the `v0.22.0` package inspection contract (`tools/gauss_package_inspection.md`, `schemas/gauss_package_inspection.schema.json`), moving package inspection from specification to real code — the same spec-then-implement split already used for environment detection (`v0.20.0` spec / `v0.21.0` implementation).

`v0.23.0`:

- Implements `scripts/gauss_package_inspection.py`.
- Provides a CLI.
- Provides an importable `inspect_packages(...)` API.
- Consumes environment-detection context or direct executable/version context.
- Preserves selected GAUSS version context.
- Avoids cross-version package mixing.
- Supports requested-package matching.
- Uses read-only filesystem inspection.
- Returns schema-shaped output matching `schemas/gauss_package_inspection.schema.json`.
- Includes self-tests.
- Includes schema-validation support.
- Accepts metadata-query flags but does not invoke GAUSS.

`v0.23.0` does **not**:

- Run user GAUSS code.
- Execute statistical analysis.
- Install packages.
- Activate licenses.
- Invoke GAUSS metadata queries.
- Activate Execution Mode.
- Implement runtime orchestration.
- Integrate package inspection into the Code Assistant workflow.
- Generate reports from actual execution output.

## Importable API Summary

**Function:** `inspect_packages(...)`

**Supported inputs:** `environment_check_result`, `executable_path`, `gauss_version`, `platform_hint`, `requested_packages`, `package_search_paths`, `allow_metadata_query`, `inspection_timeout_seconds`, `strict`.

**Test hooks (keyword-only, dependency-injection):** `path_exists_fn`, `accessibility_fn`, `list_dir_fn`, `env_detect_fn`.

**Return value:** a dictionary shaped for `schemas/gauss_package_inspection.schema.json` (plain `dict[str, Any]`).

## Input Precedence Summary

Implementation precedence, as coded in `_resolve_environment_context`:

1. Explicit executable path / GAUSS version arguments.
2. Environment check result.
3. Environment detection fallback (`detect_environment(...)` from `scripts/gauss_environment_check.py`), when allowed and not strict.
4. Unavailable/advisory fallback.

Clarify:

- The selected environment context always comes from exactly one source — never merged.
- Package results are not merged across GAUSS versions.
- Explicit user choices (path, version) carry through unchanged.
- Strict mode avoids automatic environment detection when no explicit context exists, returning `unavailable`/advisory instead.

## Version-Specific Package Context Rule

- Package inspection uses the selected GAUSS environment context, never re-detecting GAUSS itself.
- GAUSS 26 selected (environment detection's newest-version default, `v0.21.0`) means the GAUSS 26 package context is inspected by default.
- GAUSS 25 selected (explicit user override) means the GAUSS 25 package context is inspected.
- An explicit executable path carries through as the selected context.
- Package results are never mixed across versions unless explicitly requested in future functionality — verified by self-test case 9 (explicit `executable_path` is not combined with a differing supplied `environment_check_result`).
- Package availability may differ by GAUSS version.
- If the package context cannot be determined, the helper returns `unknown`/`partial`/`unavailable` rather than guessing.

## Package Discovery and Matching Summary

- Requested-package-first: `requested_packages` are classified individually; without them, status stays `unknown` rather than attempting broad discovery.
- Supplied `package_search_paths` are the primary/authoritative context — a missing or inaccessible supplied path lowers confidence toward `partial`/`unknown` rather than being silently ignored.
- Conservative derived paths (`pkgs`, `packages`) are checked as siblings of the selected executable; a missing derived candidate is silently skipped, the same pattern `scripts/gauss_environment_check.py`'s common-location scan already uses.
- Directory inspection is read-only (`Path.iterdir()` only).
- Name matching is case/separator-insensitive; no broad alias inference.
- No hidden package loading. No package import. No exhaustive all-package guarantee.

Examples:

- `tsmt`, `TSMT`, and `ts-mt` normalize to the same key.
- `tscsfit` does not automatically imply `tsmt` — `tscsFit` is one command within the TSMT package, not a synonym for the package itself, and normalization does not connect the two.

## Status Mapping Summary

- **`complete`** — requested packages fully classified (installed or missing) from a fully-scanned search scope; zero errors; `operating_mode_recommendation` restricted to `verified_knowledge`/`execution_candidate`.
- **`partial`** — at least one requested package remains `unknown` because the search scope was incomplete; requires at least one warning.
- **`unavailable`** — environment context is not `found` (or strict mode found no explicit context); `operating_mode_recommendation: advisory`.
- **`error`** — unexpected failure; `errors` has at least one entry; `operating_mode_recommendation: advisory`.
- **`unknown`** — environment found but no `requested_packages` were supplied (broad discovery intentionally not performed) or search scope was entirely absent.

Rules enforced by the implementation:

- `missing` classification requires a sufficiently complete inspection scope (no missing/inaccessible caller-supplied search path).
- `unknown` is preferred over `missing` when the scope is incomplete.
- `partial` requires at least one warning (schema-enforced).
- `unavailable`/advisory is used whenever the environment context is unusable.
- `can_assume_package_availability: true` is conservative — only returned when every requested package is confirmed installed with a fully-scanned scope.
- `missing_packages` non-empty never coexists with `can_assume_package_availability: true` (schema-enforced).

## Safety Boundary

The helper is read-only and must not:

- Run GAUSS code.
- Execute user analysis.
- Install packages.
- Modify environment variables.
- Modify user files.
- Delete files.
- Activate licenses.
- Invoke metadata queries.
- Use network access.
- Activate Execution Mode.
- Perform runtime orchestration.

Mention:

- Path exposure remains conservative/privacy-conscious — only paths actually considered or matched are included in output.
- Errors are structured (`errors: []` array) and never crash the caller; every code path returns a schema-shaped result, including a caught-exception `error` path.

## Relationship to v0.21.0 Environment Detection

- Environment detection is implemented by `scripts/gauss_environment_check.py` (`detect_environment(...)`).
- Package inspection can consume environment-detection output directly (`environment_check_result`) or call `detect_environment(...)` automatically as a fallback.
- Environment detection determines the selected executable/version context; package inspection inherits it rather than re-deciding it.
- Environment detection does not prove package availability — `found` only means GAUSS itself is detected.
- Package inspection does not activate execution — `installed: true` remains a prerequisite signal only.
- Both helpers are read-only, both return schema-valid output on every code path, and both default to Advisory Mode on any non-`found`/non-`complete` state.

## Relationship to v0.22.0 Package Inspection Contract

- `v0.22.0` specified the package-inspection contract: tool spec, result schema, five synthetic examples, and the `27.x` evaluated benchmark category.
- `v0.23.0` implements the helper against that pre-validated contract rather than inventing semantics mid-implementation.
- The schema (`schemas/gauss_package_inspection.schema.json`) and examples from `v0.22.0` remain applicable and unmodified.
- The `27.x` benchmarks remain response-behavior tests (what the Code Assistant should say), not implementation unit tests (what the helper's code does) — the two are validated separately, by evaluation and by `--self-test` respectively.
