## 1. Why

Live evaluations 73.x-78.x recorded search and grounding defects for "a later search/grounding milestone". Re-planning found one more, in the verdict path. Most fail in the safe direction (nothing is offered for execution that should not be), but three do not:
- false grounding can let `ask()` generate code grounded on an unrelated page;
- `gauss_search_docs` shows that page to a client as the answer;
- an invented function can pass as documented.

Goals:
- grounding, a generation-gate input, rests only on categorical evidence:
  - a symbol the page itself defines;
  - a curated doc-verified alias;
  - an error code;
  - a recent topic.

  It never rests on keyword overlap, a fuzzy page match, or a sentence word that happens to name a statement;
- the concepts 73.x-78.x asked about reach their documented function through curated aliases;
- an invented function is never "documented";
- every candidate can be opened by name, every excerpt keeps its Outputs, and nothing resolved is silently dropped.

**This milestone deliberately changes the `ask()` generation gate.** §6 therefore replaces "gate equivalence" with a **gate diff**: every changed tuple is listed and explained, and every row that moves toward generation is reviewed individually. Unlike the earlier draft, it also changes `validate_code` verdicts, but only for calls no page defines (finding 8, §6.3).

Constraints:
- no change to `command_doc_lookup.py` (`score_file`, `lookup`, `extract_match`) or to signature/type extraction (decision 11). Every new check reads only the `best_match` fields `lookup` already returns (`file_path`, `heading`, `syntax_blocks`);
- `compute_generation_gate`, the readiness state machine, `compute_eligibility`, `compute_evidence_profile`, every validator rule and the system-statement registry are unchanged;
- everything stays deterministic and stdlib-only: curated doc-verified aliases, exact file-name and definition checks, and no model and no score.

Out of scope: `keyword`/`fn` definitions read as undocumented calls; `.` literals as expressions; expression category inference; `&` parameters; reserved words; release readiness.

### 2.1 Finding 1: derived keyword overlap grounds unrelated pages

**Mechanism (unchanged).** `resolve_concepts` (`gauss_conversation_engine.py:907-934`) runs the documentation-derived index once over the whole question:
- a page is proposed when its heading/Purpose keywords share `MIN_KEYWORD_OVERLAP` (2) words with the question;
- page keywords are filtered (generic words, words in more than 5% of pages), but **the question's words are not**;
- a single match resolves `full`; several distinct matches are an `AMBIGUOUS` tie, and the gate maps that to `clarify`.

**Re-measured (915 questions):**
- **139 questions get a derived source**, and 51 rely on it alone.
- **35 are forced to `clarify` by a whole-question derived tie.**
- **The derived pages:** `getlrv` 23, `trace` 13, `plotSave` 7, `setColDateFormats` 6, `includedir` 5, `msym` 4, `dbIsOpenError` 3, `covmmt` 3, `fn` 3, `dbQueryGetField` 3 …
- **Plausibly right:** about ten, among them `zandrews` ("Zivot Andrews"), `matrix-division` ("slash operator least squares solution"), `range-operator` ("index operator"), `median`, `logisticRegFit`, `impute` and `meanc` (already an alias).

The draft's measurements of the rejected alternatives stand, because the code and docs are unchanged:
- a function-word list barely changes precision and creates new false groundings;
- a 3-word minimum overlap cuts resolutions to 36, still mostly wrong.

### 2.9 Finding 9: English words on statement pages

A GAUSS statement page documents a statement, not a function. Its Format is a literal block such as `run filename;`, `break;`, `new;`, `system c;`, `call function_name();` or `show -flags symbol;`, with no `.. function::` and no `name(` call form. That is a categorical, documentation-derived property: the page defines the token, but not as a call.
- **Re-measured:** 324 statement-page sources in 285 of 915 questions:
  - `run` 103, `output` 37, `print` 35, `vector` 14, `call` 13, `new` 13, `system` 10;
  - then `local`, `format`, `random`, `save`, `rerun`, `library`, `break`, `stop`, `make`, `end`, `wait`, `open` …
- **Right a few times:** `rndseed`, `dlibrary`/`dllcall` and `endp` in bare symbol lists; `transpose` alone; `save` in "Save a matrix to a CSV file"; `declare` in "Do I have to declare my structures"; `print` in "Print a message …".
- **Wrong almost everywhere else:**
  - "Run a unit root test with a structural break" → `run`, `break`;
  - "Can GAUSS call a function from a C DLL" → `call`;
  - "I need a comprehensive unit root testing library" → `library`;
  - "Fill a 6x1 vector …" → `vector`;
  - every tester-scenario prompt with "run" or "output".
- **The live consequence:** a sentence word grounds `ask()` generation on an unrelated page, and `gauss_search_docs` presents it as the answer.

## 3. Proposed design

Deterministic and stdlib-only. No new module and no `pyproject.toml` change beyond the version.

### 3.1 Derived-index matches become candidates, not grounding (finding 1)

`resolve_concepts` stops turning derived overlap into `RESOLVED` or `AMBIGUOUS`. Derived matches are listed instead as labeled `candidates` through v0.83.0's `search_candidates` path (`gauss_search_docs` only), which is structurally kept out of `GroundingBundle` and the generation gate. The draft's rejected options (B: a function-word list; C: a 3-word minimum) stay rejected (§2.1).

### 3.2 Curated aliases

Every new `ConceptAliasEntry` follows the existing discipline: real quoted `.rst` evidence, re-verified at runtime. The final list comes from the §6.2 gate diff; the starting set is:

| Phrases | Symbol / page | Evidence |
|---|---|---|
| `percentile`, `percentiles` | `quantile` | `:param e: quantile levels or probabilities`; example prints "95 percentiles" |
| `sort by a column`, `sort a matrix by a column`, `sort by column`, `sort on a column`, `sort rows by a column` | `sortc` | `:param c: … specifies the column(s) of x to sort on` |
| `endfor` | `for` | `for.rst` Format: `for i (start, stop, step); … endfor;` |
| `cholesky decomposition` | `chol` | `chol.rst` Purpose |
| `zivot andrews`, `zivot-andrews` | `zandrews` | `tsmt/zandrews.rst` Purpose |
| `least squares solution`, `slash operator` | `matrix-division` | `matrix-division.rst` Purpose |
| `column medians`, `median of each column` | `median` | `median.rst` Purpose |
| `logistic regression` | `logisticRegFit` | its Purpose |
| `save a matrix`, `save to a file`, `save … to a file` | `save` | `save.rst` Purpose (a statement; §3.8) |
| `structure`, `structures`, `struct` | the structures user guide | `user-guide/advanced/structures.rst` heading |
| `declare a structure`, `declare structures` | `declare` | `declare.rst` Purpose |
| `index operator`, `reorder columns` | `range-operator` | `range-operator.rst`: "Inside brackets, creates an index range" |

The draft's rule "an alias supersedes the derived pass" is moot under §3.1, because the derived pass no longer resolves anything.

### 3.3 A one-word query is looked up even if it is a stopword (finding 4)

In `_candidate_tokens`, when the question is exactly one token (after trimming whitespace and a trailing `?`), that token is a candidate even if it is in `_STOPWORDS`. Multi-word questions are unchanged.

### 3.4 Hyphenated page names (finding 5)

A hyphenated word (`[A-Za-z][A-Za-z0-9_]*(?:-[A-Za-z0-9_]+)+`) is a candidate token **only when a page with exactly that stem exists** (the cached stem scan `_known_symbol_stems` already reads). Otherwise it is split as today.

### 3.5 Outputs survive the excerpt budget (finding 6)

When the assembled text exceeds `max_chars` and Outputs would be cut, `_format_doc_match` shortens Inputs first (ending in `…`) so that heading, syntax and Outputs fit. Pages that already fit are byte-identical. The section order is unchanged. Expected: exactly the 33 §2.5 symbols change at 1,500.

### 3.6 Every grounding re-lookup reads the defining page (finding 7)

The three remaining sites use `_lookup_defining_page`, each keeping its own status and confidence checks. `lookup` is unchanged (decision 11).

### 3.7 A token grounds only on a page that defines it (finding 8)

One helper, `_page_defines(token, best_match)`, implements the §2.7 test (stem, heading symbol, or whole word in the syntax blocks). It is applied in three places:
- the literal-token loop in `resolve_concepts`: a non-defining `found` match becomes `UNRESOLVED` (an unmatched topic). The page is still listed as a search candidate;
- the per-symbol loop in `validate_code`: a call whose page does not define it is `unmatched`, so the call is an unknown symbol and the snippet is `not_ready` with the existing reason ("unresolved/unsupported call symbol(s): solve");
- the same check in `validate_generated_code`'s extra signature lookups, so `ask()`'s post-generation check agrees.

### 3.8 Statement pages ground only when the word is code-marked (finding 9)

A page documents a **statement** when it defines the token (§3.7) but its syntax blocks contain no `token(` call form. A literal token whose page is a statement page grounds only when the token is **code-marked** in the question:
- the question is that one token;
- the token is inside backticks or quotes;
- or the question is a bare symbol list: no stopword, and every candidate token resolves literally (`rndn rndseed meanc stdc`, `dlibrary dllcall`).

Otherwise it is a search candidate, labeled as a statement page, and not an unmatched topic, because it was never a topic. Curated aliases (§3.2: `save`, `declare`, `endfor`) restore the measured right cases. Decision 3 offers the alternatives.

### 3.9 Navigation pages never ground (finding 10)

A page whose file name is `index.rst` never grounds, from a literal token or an alias. It can still be listed as a candidate. The 24 pages are toctree navigation with no Purpose or Format.

### 3.10 Nothing resolved is dropped silently (finding 11)

- **Report what is cut.** `GroundingBundle` gains `omitted_topics`: symbols that resolved but were cut by `MAX_RESOLUTIONS` or `MAX_GROUNDING_SOURCES`. An omitted topic makes the bundle `partially_grounded`, as an unmatched one does. So `ask()` generates for the included topics only, and says what was left out.
- **Show it in search.** `gauss_search_docs` returns `omitted_topics` and a fixed note: "Resolved but not included (at most 4 per search); search these names separately."
- **Fix the ranking.** `_token_priority`'s tier 3 uses the documented-symbol set, meaning the concept index's symbols, already built and cached, instead of file stems. A symbol on a combined page (`invpd` on `invinvpd.rst`) then ranks with the other named functions.
- **The bounds stay where they are** (decision 9).

### 3.11 The 78.x carry-overs (finding 13)

- **`KNOWN_LIMITATIONS.md`:** one pending request per session, but a client can open several sessions; with several prompts open, the client alone decides which one a bare reply answers.
- **`gauss_execution_decide`'s description and the server instructions** gain one sentence: "If several prompts are open, the user names the prompt in a separate message and replies with a bare yes or no; never ask the user to label a reply."

No behavior changes.

### 3.12 What does not change

- `command_doc_lookup.py` in full, and every extraction function.
- `compute_generation_gate`, `search_candidates`' ranking and labels, `MIN_KEYWORD_OVERLAP`, `MAX_DOC_FREQUENCY_FRACTION`, and the derived index itself (it still feeds candidates).
- Every validator rule, the system-statement registry, the readiness state machine, `compute_eligibility` and `compute_evidence_profile`.
- The 87-word `_STOPWORDS` for multi-word questions.
- The execution handoff, apart from §3.11's text.

## 4. Scope boundary

In scope: §3.1-§3.11, the `KNOWN_LIMITATIONS.md` entries for §5, and `docs/mcp-server.md` (the new `omitted_topics` field).

Out of scope:
- `.. include::` expansion (finding 12, decision 10);
- indexing parameter text for the derived index;
- stemming and synonyms;
- English words that name *functions* (`rows` in "a matrix with rows [4, 1]"; §5);
- a `tspdlib` package-name alias;
- the §1 out-of-scope items.

## 5. Known limitations this design accepts

- **Recall for plain-language concepts rests on curated aliases.** A question naming no symbol and matching no alias is `ungrounded`. `ask()` blocks it, and `gauss_search_docs` lists candidates. This is the safe direction, and §3.2 restores every measured right case.
- **Strict-mode `ask()` blocks more ordinary requests** (decision 3): about 230 of the 915 questions lose all grounding, most of which rested on `print`/`vector`/`run` pages.
- **A statement asked about in prose needs an alias or code marks.** For example, "how do I exit a loop with break" does not ground `break`; "`break`" or "break" alone does.
